# 3D 模型资产导入规范

本目录只存放已经核对来源与许可、并准备进入 Godot 项目的模型。当前目录下尚无已验收的外部模型包；Quaternius、Kenney、Poly Haven、KayKit 仍是候选来源，不代表模型已经下载或导入。

## 目录约定

- `characters/`：玩家、 humanoid NPC、人形敌人。
- `monsters/`：四足怪物、异形怪物、Boss。
- `buildings/`：建筑主体与可复用建筑模块。
- `environment/`：岩石、树木、墓碑、地表和环境道具。
- `source/`：仅在仓库体积与许可允许时保留原始工程文件；大型源文件优先放独立美术归档，不要提交未经确认的大包。
- 每个资产包使用独立子目录，避免同名贴图、材质和动画互相覆盖。

## 导入前检查清单

1. **许可**：打开具体资产包的发布页，确认该包的许可版本；保存随包 LICENSE、README、作者、原始下载页和下载日期。不能仅凭资源站首页或作者其他作品推断授权。
2. **文件完整性**：优先使用 GLB/glTF 2.0；检查模型引用的贴图、材质和动画是否齐全。
3. **比例与朝向**：统一 1 Godot unit = 1 meter、Y 轴向上、角色正面朝 -Z；人形角色目标高度约 1.7–1.9 m。
4. **骨架与动画**：检查骨骼命名、根骨骼、骨盆朝向、脚底位置、蒙皮权重；确认 Idle/Walk/Run/Attack 等动画真实存在且动作没有明显拉扯。
5. **材质**：检查贴图色彩空间、透明模式、法线方向、粗糙度和金属度；避免不必要的 4K 贴图。
6. **性能**：记录三角面数、材质数、贴图尺寸；可见距离较远的资产优先准备 LOD 或低模版本。
7. **碰撞**：游戏碰撞使用独立简化碰撞体，不直接将高面数渲染网格作为动态角色碰撞。
8. **场景验收**：在实际第三人称镜头下检查轮廓、比例、脚底接地、动画循环、阴影和材质表现，再替换程序化占位模型。

## 文件命名

- 文件名使用小写英文与下划线，例如 `player_wanderer_v01.glb`。
- 贴图与模型使用稳定前缀，例如 `player_wanderer_body_basecolor.png`。
- 不覆盖已验收版本；更新使用递增版本号，并在资产登记表中说明替换原因。

## 资产登记

每个外部资产在 `../3d/asset-register.csv` 中登记：

- asset_id、类别、名称；
- 原始来源 URL、包名与版本；
- 许可名称与许可文件位置；
- 本地文件路径、修改内容；
- 状态：candidate / downloaded_unverified / imported_unverified / accepted / rejected。

只有完成许可核验、导入和场景验收后，状态才能标记为 accepted。下载成功不等于导入成功，导入成功也不等于美术验收通过。

## Godot 导入建议

- 先把单个模型包放入对应子目录，不要一次性导入整个资源合集。
- 通过 Godot Import 面板检查 Mesh、Skin、Animation、Material 设置。
- 角色模型优先保留原始骨架和动画，再评估重定向；不要未经验证就合并骨骼或重命名动画轨道。
- 先建立一个测试场景验证模型朝向、身高、动画和碰撞，再接入正式玩家/NPC/怪物场景。
- 记录 Godot 版本、导入选项和必要的材质修正，保证其他开发环境可复现。

## 当前状态

玩家、NPC、怪物和酆都鬼门关仍以项目内原创程序化模型作为可替换占位。外部 CC0 模型仅列为候选；没有实际文件进入仓库前，不得在功能说明中称其已接入。
