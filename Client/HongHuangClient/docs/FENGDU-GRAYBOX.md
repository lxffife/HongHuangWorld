# 酆都天城 3D 灰盒（可漫游原型）

状态：可行走空间原型持续迭代；尚未完成 Godot 编辑器运行验收。已加入城外山体轮廓、四向官道、雾效、街道魂灯、桥梁护栏，中式四面坡屋顶、翘檐和简化斗拱轮廓，并为主要官署增加差异化地标；仍是程序化几何灰盒。

## 运行方式

在 Godot 4 项目中直接打开并运行：

`Client/HongHuangClient/scenes/FengduCityGraybox.tscn`

这是一张独立的美术/导航灰盒场景，不替换当前线上世界入口，也不改变世界服务器当前只开放青云人界的配置。

## 第一轮空间尺度

- 城内边界：约 192m × 192m（城墙中心线）。
- 护城河：环绕城墙外侧，宽约 7m。
- 城墙：高约 13m，四门留有通道；桥面两侧增加石质护栏。
- 城外：增加远景山体轮廓、四向官道、低密度冷色雾效。
- 城内：增加主街魂灯、城区入口前场，使用自发光几何体控制性能。
- 建筑：屋顶由单层盒状占位升级为四面坡屋顶组合，加入檐口金属色压边、四角翘檐提示和简化斗拱；已应用于城门楼、皇城正殿及官署占位建筑。
- 官署差异化：十王府增加两侧审判院落；判官司增加案卷楼和廊房；鬼籍司增加多层魂籍藏书楼；功过司增加功过双殿；轮回司增加轮回门；阴兵大营增加营房和瞭望台；引魂驿站增加接引雨棚；巡城司增加烽望塔。
- 万魂鬼市：改为中央交易主街、两侧朝向主街的六组摊位、拍卖台、后勤侧巷、鬼市告示和悬赏榜、悬挂魂灯；预留摊主与交易活动点位。
- 万家魂坊：改为四组错落住宅小院、中央公共广场与古井、茶亭和社区魂灯；预留居民聚集点位。
- 阴兵大营：增加开阔操练场、两侧营房、瞭望岗、兵器架、训练木桩和军令桌；预留操练与军需 NPC 活动点。
- 引魂驿站：形成到达通道、登记台、排队栏、候魂亭和分流门的连续动线；预留引魂使与候魂者活动点。
- 巡城司：增加巡防值守岗、调度厅、巡逻路线案桌和信号塔；预留巡逻集合点。
- 道路：建立三级道路层次：南北/东西 13m 主轴、6m 官署分配道路、4m 城区外围联络巷；皇城另有仪仗步道。
- 院落：主要功能区增加低矮围墙、南向门洞、门柱、门楣和内院铺装引导线；入口净宽按区块尺度控制在约 5–7m。
- 城门：四门加入向两侧开启的门扇和门钉视觉细节；门扇目前是无碰撞装饰，保留灰盒漫游通道。
- 皇城：位于城市北部核心区，增加独立宫城外墙、午门、承天门两重礼制门禁、前朝广场、左右配殿、后殿、回廊和庭园水池；南向主入口保持开放，主殿仍为最高视觉锚点。
- 九大核心功能区：十王府、判官司、鬼籍司、功过司、巡城司、轮回司、万魂鬼市、万家魂坊、酆都皇城。
- 专门设施：阴兵大营、引魂驿站；四门：北天门、南幽门、东玄门、西冥门。

## 操作

- WASD / 方向键：移动
- 空格：跳跃
- 鼠标左键：捕获视角
- 鼠标移动：转向
- ESC：释放鼠标
- E：与附近 NPC 交互（约 3.8m 内）
- F6：显示/隐藏活动点调试标记

## 重要边界

1. 这是客户端灰盒；已加入无碰撞的本地 NPC 视觉原型、稳定原型 ID、交互元数据和占位交互反馈，但这些 ID 不是服务端权威身份，不包含真实碰撞、商店交易、任务、拍卖、门禁或服务端区域权限。
2. 碰撞只用于本地漫游验证；服务端权威移动和区域边界仍是最终规则。
3. 酆都与血海分属不同远域，血海不出现在本城灰盒中。
4. 城区占位、道路宽度和建筑比例是第一轮可调整参数，需通过实际运行和双人/多人移动测试后再冻结。
5. 目前用程序化基础几何验证体量和路线，不代表最终国风建筑美术品质；屋面板仍是低模块体组合，尚未实现真实曲面瓦片、榫卯细节和脊兽模型。
6. 新增屋顶、斗拱、官署差异化装饰及城门门扇均为无碰撞装饰网格；后续需在 Godot 实机检查屋面接缝、檐角比例、门扇视觉角度、遮挡和 draw call，再决定是否改为合并网格或 MultiMesh。
7. 官署院墙具有本地碰撞，入口保持开放；需要实机漫游确认玩家胶囊体能顺利穿过门洞，并检查围墙与建筑装饰是否相交。
8. 皇城采用独立宫城边界和双重宫门，午门与承天门之间为前朝空间；左右配殿、后殿、回廊及水池目前均为程序化占位，尚未加入室内、宫廷 NPC 和交互。


## 鬼市与魂坊布局说明

- 鬼市摊位采用低模柜台、后仓、遮棚和招牌组合；中央主街保持连续，拍卖台位于街道北端，后巷承担未来补货/服务 NPC 的空间预留。
- 魂坊以四组非完全对称的小院围绕公共广场布置，住宅院墙留出朝向公共通路的入口；古井和茶亭作为社区活动锚点。
- `npc_spawn_points` 保留为兼容层；场景初始化时会转换为统一的 `activity_points` 记录，字段包括区域、角色、活动、位置、朝向、时段标签、容量和活动半径。
- 活动类型目前覆盖鬼市摊主交易待机、魂坊居民社交、阴兵操练、引魂登记、巡城值守；这些是客户端本地规划数据，不会创建真实 NPC，也不是服务端出生点。
- 按 F6 可显示/隐藏活动点调试标记，颜色区分商贩、居民、阴兵、引魂使和巡城卫；默认关闭，不影响正常场景画面。
- 巡城司增加一条沿 x=0、x=±34 主街及 z=±32、z=±78 联络道路布置的闭环巡逻规划线。它只是道路节点与调试连线，不是 NavigationAgent 路径，也没有 NPC 移动或服务端同步。


## 军营、接引与巡防空间

- 阴兵大营的操练场位于院落中部，营房与兵器架沿边布置，避免将主要训练通道切断；训练木桩仅为无交互灰盒道具。
- 引魂驿站按“到达—登记—候魂—分流”组织空间，排队栏和分流门用于表达流程，尚未实现实际队列或轮回分配逻辑。
- 巡城司由调度厅、巡防岗、信号塔和路线案桌构成；目前登记的是 NPC 候选活动坐标，尚未实现动态巡逻路径、寻路或同步。


## 本地 NPC 活动原型

- 场景初始化时按活动点生成本地低模人物：鬼市商贩、魂坊居民、阴兵、引魂使和巡城卫；另外生成一名沿巡逻闭环移动的巡城卫。
- 角色由胶囊体、球体和基础几何组合，不依赖外部模型或付费资源；商贩有头饰轮廓，阴兵携带长枪，引魂使携带发光魂灯。
- 活动点朝向按区域用途设置：鬼市摊主朝向交易街、阴兵朝向操练场、引魂使朝向城内接引方向，魂坊居民围绕公共广场形成交流朝向；巡逻卫随路线方向转身。
- 待机动作按角色区分并错开节奏：商贩做轻微招呼动作，居民短暂转向交流，阴兵进行持械准备动作，引魂使翻看登记册并抬手引导；巡逻卫沿闭环路线移动。
- 本地演示时钟从 18:00 开始，每现实 1 秒推进 1 个游戏分钟；鬼市摊主在 18:00–06:00 出现，白天休市隐藏，阴兵在 06:00–22:00 操练、其余时间休整。该时钟仅供灰盒演示，不是服务端世界时间。
- 引魂驿站新增三名候魂者占位 NPC，沿入口栏杆排队，面向登记台；引魂使与候魂者共享 28 秒本地演示节拍，按队首到队尾依次完成三轮：查册、叫号、应答、登记完成。已登记者保持原队列槽位并切换完成姿态，交互反馈可说明其登记状态；下一位在下一轮成为叫号对象。由于当前登记台与排队栏之间没有经过实机验证的安全离队通道，本轮不伪造角色位移、不让 NPC 穿桌或穿栏杆，也不宣称已实现队列补位/离队。此逻辑仅为客户端状态演示，真实队列顺序、登记结果和出队必须由游戏服务端管理。
- NPC 按与玩家的距离分级更新：近处逐帧更新，中距离约 0.32 秒更新一次，远距离约 0.8 秒更新一次；远处动画会更简化/间歇更新，以控制后续人口扩展成本。
- NPC 已建立本地稳定原型 ID、显示名、所属区域、角色、交互类型和重要度字段；普通活动点 ID 按区域/角色/序号生成，巡逻路线节点有独立 ID，巡逻行走者使用固定 ID。后续服务端接入时必须以服务端 actor ID 为准，不能把这些客户端 ID 当作账号或权威实体 ID。
- 玩家靠近可交互 NPC 约 3.8m 内时，HUD 显示 `E 交互` 与 NPC 名称；按 E 可查看当前占位对话/交互反馈。商贩、引魂使、候魂者、阴兵/巡城卫、居民分别标记交易、登记、队列说明、军务、闲谈类型。
- 当前交互仅为本地说明反馈，不会创建真实商店、登记流程、军令、任务或聊天记录；NPC 仍无碰撞体，不参与物理、寻路、战斗或服务端同步。
- 巡逻 NPC 通过道路节点插值移动，不使用 NavigationAgent3D，也不代表服务器权威移动。


## NPC 角色行为状态机

- NPC 初始化时按角色建立本地行为状态序列，并记录当前状态、状态持续时间、已运行时间和循环索引；状态更新复用现有 NPC 距离 LOD 累计时间，不另起每 NPC 独立 Timer。
- 鬼市商贩在夜市营业时循环表现交易待机、招呼、整理货物等动作；玩家靠近摊位约 5m 时，商贩会优先转入招呼姿态，离开后恢复原有动作循环；商贩始终留在摊位活动点，不会为招呼玩家穿越柜台或主街。清晨随夜市时段隐藏。当前仍是原地姿态表现，没有实际货物搬运、交易或摊位库存。
- 魂坊前四名居民沿公共广场四角的闭环 Waypoint 低速行走，路线避开中央古井和茶亭建筑；第五名居民仍在茶亭附近原地活动。居民走动使用现有 NPC LOD 累计时间推进，移动朝向优先于社交动作朝向。当前只在广场开放区域内移动，不跨院墙、不穿越住宅或茶亭。
- 阴兵白天在列队准备与操练动作间切换，夜间状态被强制锁定为休息，避免状态循环覆盖昼夜作息。
- 引魂使在查阅登记册、抬手引导和登记待机间切换；三名候魂者保持各自队列槽位，队首周期性进入叫号应答动作，后两位继续等待或短暂张望。叫号动作只改变上肢与身体姿态，不移动根节点，因此不会穿过柜台或排队栏；尚未实现真实队列推进、离队、补位和登记。
- 魂坊广场首批区域内 Waypoint 已启用：四个角点对应现有居民站位，闭环路线避开井台；路径只用于这块开阔广场，不代表通用寻路系统。
- 状态机与 Waypoint 目前负责客户端表现层，不负责动态避障、碰撞、任务、交易、排队推进或服务端 AI；跨设施移动必须等导航网格、障碍检测和卡死恢复机制具备后再开放。

## 区域人口调度与距离 LOD

- NPC 初始化后按所属城区建立 `npc_population_by_district` 索引；区域人口管理器统一计算每个城区与玩家的最近距离，并标记 `near`、`mid`、`far` 区域层级。
- 单个 NPC 的更新间隔再结合精确距离和重要度计算：60m 内逐帧更新；60–110m 基础约 0.32s；110m 以外基础约 0.8s；220m 以外最低约 1.2s。关键 NPC 的间隔减半，远景/环境 NPC 的间隔增加 50%。
- 区域层级用于集中管理与后续按区域启停模拟；当前版本仍保留每个可见 NPC 的轻量动画更新，尚未实现真正的区域卸载、对象池、服务器人口分片或数百 NPC 压力测试。
- 距离降频使用累计 elapsed 推进巡逻路线，避免低频更新造成路线速度随帧率变化；NPC 仍是本地视觉表现，不拥有独立 AI 决策循环。
