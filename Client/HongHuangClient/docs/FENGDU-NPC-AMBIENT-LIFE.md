# 酆都 NPC 环境行为与待接入规范

## 本轮已实现：岗位化待机动作

客户端 `world_scene.gd::_animate_npc_visuals()` 为当前已加载的 NPC 增加低频、错相的岗位待机动作：

| NPC 类型 | 待机表现 |
| --- | --- |
| 阴兵（guard） | 头部缓慢巡视，手臂保持警戒姿态 |
| 判官（judge） | 轻微抬手，配合克制的审判点头 |
| 试炼使者（trial_master） | 手臂轻微调整，令令牌缓慢摆动 |
| 铁匠（blacksmith） | 低频、周期性举锤动作 |
| 孟婆（soup_keeper） | 保持奉汤姿态，双臂细微调整，汤碗雾气继续起伏 |
| 普通居民 / 其他 | 轻微呼吸与头部观察 |

动作只修改客户端视觉节点，不修改 NPC 服务端坐标、交互半径、寻路状态或任务状态。它不会让 NPC 在地图上巡逻，也不会影响服务器权威判定。

## 本轮新增：NPC 面向玩家的交谈反馈

- 中心服成功返回 NPC 交互结果后，客户端为对应 NPC 设置约 3.2 秒的交谈表现窗口。
- 交谈窗口内，NPC 会平滑转向当前玩家，并叠加简短招呼手势与轻微点头；窗口结束后自动回到巡逻朝向或原有待机动作。
- 该表现只在交互成功响应后触发，不会提前显示“交互成功”，也不会改变 NPC 位置、交互距离、任务或因果状态。
- 当前手势仍依赖程序化 NPC 的手臂/头部节点；正式骨骼模型接入后，应将此状态映射到模型的 talk / greet 动画，而不是继续旋转占位节点。


## 本轮新增：酆都南门守备与鬼市摊位 NPC（迁移 000078）

- 南城门阴兵 `fengdu_south_gate_guard`：按酆都城布局预览中的南门中心（0, 0, 36）布置，在城门内侧矩形区域巡逻；路线闭环、低速、带岗哨停留。
- 鬼市西市纸钱铺掌柜 `fengdu_ghost_market_vendor_west`：放置在西侧摊位附近，提供纸钱铺主题对话。
- 鬼市东市魂灯摊主 `fengdu_ghost_market_vendor_east`：放置在东侧摊位附近，提供魂灯主题对话。
- 三个 NPC 都由 `world_npc_definitions` 提供，客户端只负责显示与交互；城门阴兵的位置仍由中心服按 UTC 路线计算。
- 两名商贩目前是固定摊位 NPC，**尚未接入真实商品目录、库存、价格和交易扣款**；对话文案明确说明交易以中心服数据为准，不能将其视为已完成商店系统。
- 部署时在 000077 之后执行 `000078_fengdu_gate_and_market_npcs.up.sql`；回滚使用同名 `.down.sql`。

## 重要边界

- 正式 GLB 若没有对应的程序化节点名称（例如 `ArmPivotRight`、`HammerHandle`），上述局部动作会自动跳过；正式模型应优先使用自身骨骼动画。
- 当前场景中的程序化 NPC 仍是占位模型，不代表孟婆、判官、阴兵和铁匠的最终角色资产。
- 本次没有导入外部 GLB、动画包或音频文件。
- 当前修改尚未经过 Godot 编辑器解析、运行场景或多人联机测试。

## 本轮新增：服务端权威阴兵巡逻

- 数据库迁移 `000077_npc_patrol_routes` 为 NPC 定义增加 `behavior_profile` 与 `patrol_route`。
- 轮回殿守卫 `fengdu_reincarnation_guard` 配置四点闭环巡逻路线、速度和停留时间。
- Backend 使用服务端 UTC 时钟按路线计算位置；相同路线与时间在所有服务端实例得到相同结果。
- NPC 列表响应返回巡逻路线与当前路线相位，客户端从该相位开始插值，避免只在刷新列表时跳位置。
- 交互校验改为使用服务端实时计算的 NPC 位置，并与服务端保存的角色坐标计算距离；客户端不能伪造巡逻位置或交互距离。
- 客户端最近 NPC 提示与 F 键目标选择改为使用正在移动的 NPC 节点位置。
- 路线校验限制：2–32 个点、速度 0.1–8 m/s、单点停留不超过 120 秒、必须闭环；无效路线回退静态坐标。

## 下一阶段：扩展服务端权威 NPC 生活系统

真正的巡逻、值守、营业与昼夜作息应由服务端提供状态，客户端仅插值表现：

1. NPC 定义增加行为配置：`behavior_profile`、`home_anchor`、`route_id`、`schedule_id`。
2. 服务端按区域和玩家可见范围更新 NPC 状态，避免全地图 NPC 高频模拟。
3. 阴兵：城门岗哨、城墙巡线、交接班；巡逻路线需有明确停留点与转向点。
4. 居民：住宅、鬼市摊位、衙门办事点之间的定时移动；夜间活动与区域开放规则由世界时钟驱动。
5. 关键 NPC（孟婆、判官、试炼使者）保持固定服务位置，不因日常作息离开交互锚点。
6. 客户端收到权威路径/状态后做平滑移动、朝向和动画状态切换；交互位置以服务端状态为准。
7. NPC 音效按行为事件触发并做距离衰减，不在每帧循环创建音源。

## 验收标准

- 同一 NPC 对所有玩家的位置、行为阶段和交互结果一致。
- 断线重连后能从快照恢复 NPC 当前状态。
- 玩家靠近交互时，NPC 不会因客户端本地动画偏移导致交互距离失效。
- 低端设备按可见范围、LOD 和更新频率控制开销。
- 正式模型的 idle / walk / work / talk / combat 动画通过模型资产验证器检查。


## 部署注意

首次启用巡逻前，先在中心服数据库执行 `Database/migrations/000077_npc_patrol_routes.up.sql`。回滚时执行对应 `.down.sql`。未执行迁移的旧数据库不包含巡逻字段，新的 Backend 版本不能直接启动；部署应先迁移数据库，再重启 Backend。
