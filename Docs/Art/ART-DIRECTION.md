# 洪荒·诸天轮回 — 客户端美术方向

## 目标

Godot 4.6 第三人称 3D 国风仙侠 MMO。先建立统一、可读、可替换的风格化 3D 视觉体系；不以大量高面数资产换取短期观感，也不让临时模型进入服务端权威逻辑。

## 视觉支柱

1. **东方仙侠轮廓**：飞檐、斗拱、石阶、松树、玉石、符纹、灵光；建筑轮廓远距离可识别。
2. **克制的灵气表现**：灵魂/法术可有柔和自发光，但不遮挡角色、怪物攻击预警和交互目标。
3. **自然材质与层次**：石、木、铜、玉、布、雾分别使用不同粗糙度/金属度；避免所有物体像同一材质。

## 当前色彩方向

- 青云界：松绿、石灰、暖木、青玉、日光金；天空偏蓝，远景带轻雾。
- 冥界酆都：蓝黑、烟紫、冷石、幽蓝灵火、低饱和青灰。
- 玩家：主体颜色与当前种族/装备有关，轮廓必须和地面及怪物区分。
- 怪物：按种类建立剪影差异；危险攻击使用独立预警色，不仅依赖颜色，也配合动作/形状提示。

## 生产约定

- Godot 单位按米；角色高度目标约 1.7–2.0m，普通门柱/门楼按可通行尺度设计。
- 原创程序化模型集中在 `scripts/*_visual_factory.gd`，只负责表现，不包含战斗/网络/掉落逻辑。
- 可替换外部模型优先 GLB/glTF 2.0；导入后核对单位、朝向、材质、贴图路径、骨架、动画、碰撞和 LOD。
- `VisualModelLibrary` 维护模型键到 GLB 路径的映射；资源缺失或导入失败时必须回退程序化模型。替换模型不得改变碰撞体、网络同步或服务器权威战斗。
- 角色/怪物碰撞体由玩法脚本控制，不直接依赖艺术网格的复杂碰撞。
- 远景建筑使用简化碰撞；可通行入口必须保留通道，不允许整栋建筑单一碰撞盒封死入口。
- 重复树木、石块等采用低面数网格/实例化；远景优先低成本材质。
- 当前程序化模型是可替换 blockout，不宣称达到最终商业美术品质。

## 当前进度

- 已有：冥界鬼门关、奈何桥、轮回殿轮廓、冥界 NPC/怪物程序化模型；怪物包含荒原狼、铁骨兽、战魂、生命/疾风游魂，以及新增的火灵/冰魄视觉分支；玩家当前以灵魂光团表现，转入人界后使用带衣袍层次、玉饰和发冠的原创人形原型。
- 本轮新增：青云宗山门、青云大殿、分层松树程序化模型；强化人形玩家的衣袍层次、玉饰、发冠与剑鞘细节。
- 本轮新增：玩家普通攻击本地挥剑表现（仅响应已发送的攻击输入，不决定命中）；火灵蓄力火球外扩、冰魄冰冠/冰环蓄势动作，均复用服务器下发的 windup/impact/recovery 阶段。
- GLB 可替换入口：`scripts/visual_model_library.gd` 已接入玩家与全部怪物原型（狼、铁骨兽、战魂、生命/疾风/火灵/冰魄游魂）；缺少 GLB 时回退程序化模型。目前未附带或下载第三方模型。
- 远程玩家：青云界使用与本地一致的人形衣袍模型，并按网络位置插值驱动待机/行走肢体；冥界继续使用灵魂光团和旋转灵环。
- 怪物动画适配：`scripts/monster_animation_driver.gd` 遍历导入 GLB 的 AnimationPlayer，按 idle/move/attack/hit/death 常见命名匹配并缓存片段；荒原狼、铁骨兽、战魂及各类游魂优先播放模型原生动画，缺少兼容片段时继续使用原有程序化动作。死亡状态保持到尸体清理，原有服务端攻击阶段、受击计时、死亡淡出与服务器权威判定不变。
- 人形动画适配：`scripts/humanoid_animation_driver.gd` 自动查找导入 GLB 内的 `AnimationPlayer`，按 idle/walk/attack/hit 常见命名匹配动画；本地与远程人形优先播放模型原生动画，缺少 AnimationPlayer 或匹配片段时回退程序化 Pivot 动画。动画仅改变客户端外观，不参与服务器移动和命中判定。
- 战斗反馈：服务器 windup/impact 阶段驱动火灵/冰魄地面预警环；预警有脉冲，impact 关闭；命中加入按怪物属性区分的短促闪光，暴击更醒目。
- 人形装备挂点：程序化玩家模型新增武器、头部、胸甲、腿部、鞋子、背部、饰品、副手挂点；装备接口读取服务端已装备列表，在本地模型生成品质色阶的占位外观。GLB模型若未内置挂点，客户端会补建标准挂点。 武器/副手挂点在程序化人形中跟随左右手臂 pivot，攻击挥臂时武器同步摆动；GLB 缺少可识别手臂挂点时仍使用躯干 fallback。
- 战斗事件字段复核：客户端命中表现读取 `critical`、`defeated`、`damage` 等现有事件字段；怪物攻击阶段读取 `phase`、`attack_style`、`windup_ms`、`recovery_ms`。表现继续服从服务器事件，不在客户端推导命中。
- 怪物死亡表现：实体/战斗事件由服务器确认 `defeated` 后触发；狼、铁骨兽、战魂等实体怪物采用倾倒、缩小与淡出，冥界游魂采用旋转上升、灵体收缩与消散。客户端只表现死亡过程，实体移除/重生仍以世界服务器快照为准。
- 轮回出生体质表现：`character_birth_inheritance` 保存的出生继承记录通过当前角色状态返回；客户端按服务端记录的主导资质（力量/体魄/敏捷/灵识/元气）选择轻量灵纹色调，并按灵魂成长阶段显示环纹/灵气外壳。该效果只作外观识别，不修改属性、移动或战斗判定；尚未轮回的角色不显示先天继承纹饰。
- `ASSET-REGISTER.csv` 已登记当前原创程序化建筑、树木、玩家与怪物模型；内部程序化资源与第三方素材分开记录，项目发布许可仍需项目方最终确认。
- 后续：远程玩家攻击/受击事件同步（需确认服务端事件字段）、模块化宗门建筑/村镇、地表材质与远景山体。


## 远程玩家出生体质表现

- 世界入场快照携带角色的出生继承摘要，世界服务器将其作为只读外观字段保存在玩家实体状态中。
- 玩家加入事件与 20Hz 实体快照都广播 `birth_inheritance`，保证新加入玩家和已在场玩家看到一致的体质灵纹。
- 客户端按 `dominant_attribute` 选择灵纹主色，按 `source_growth_stage` 调整光效强度与外壳尺度。
- 冥界仍显示灵魂光团，不叠加人界出生体质外观；投胎进入人界后显示出生继承灵纹。
- 该字段仅用于表现，不参与移动、伤害、属性计算或权限判断；缺失/空对象时隐藏灵纹。


## 远程玩家装备外观同步

- 世界入场快照从当前角色装备栏读取槽位、物品标识、名称和品质；世界服务器只保存并广播外观摘要。
- 玩家加入事件和实体快照都携带 `equipment` 数组；客户端仅在摘要变化时重建远程装备，避免每帧重复创建节点。
- 远程装备使用与本地装备一致的品质色阶和程序化原型外观；武器/副手优先挂到左右手臂Pivot，其他槽位使用身体挂点。
- 客户端优先复用导入模型已有挂点，只清理自身生成的 `EquipmentVisual`，不删除模型原生节点。
- 本地与远程玩家共用 `scripts/equipment_visual_factory.gd`：优先使用模型已有装备 socket，其次识别程序化左右手 pivot，再按常见中英文/Mixamo 骨骼别名创建 `BoneAttachment3D`；无法识别骨骼时回退到标准人形坐标挂点。
- 装备挂点与槽位网格生成均由 `HHEquipmentVisualFactory` 统一：本地/远程玩家调用同一品质色阶、武器/防具/饰品程序化模型工厂，减少双端外观尺寸与材质漂移；装备节点带 `item_id` 元数据，仅用于表现追踪。
- 远程装备刷新会清理表现层识别的槽位（含背部/副手），并对网络装备槽位执行白名单校验；这不代表背部/副手已开放为正式可装备槽位，未知槽位不会创建客户端节点。
- 装备属性、装备合法性和战斗数值仍由后端/世界服务器权威处理；快照装备字段只负责展示。


### 玩家动作事件同步

- WorldServer新增`PlayerActionEvent`（协议类型21），只广播服务端验证通过的攻击动作，以及服务端实际结算的受击动作；事件包含角色ID、动作类型和来源信息，不携带客户端伤害数值。
- 广播排除动作发起者/受击者连接，避免本地预测动作重复播放；攻击者本地仍即时响应输入，受击者仍使用自己的CombatEvent更新生命与倒地状态。
- 其他客户端按角色ID驱动远程人形GLB的attack/hit动画，缺少原生片段时回退手臂程序化动作；受击者本地也会播放hit动画并保留摄像机震动；冥界魂光形态使用缩放脉冲表达动作。动作事件仅用于表现，伤害、距离、冷却和生命仍由WorldServer权威处理。


### 武器动作分类与动作优先级

- WorldServer 从入场时保存的服务端装备快照读取 `weapon` 槽位，按武器名称/标识映射为 `sword_slash`、`spear_thrust`、`ranged_shot`、`staff_cast`；未知武器回退 `melee`。该映射只决定客户端动作，不开放客户端指定攻击类型，也不改变当前服务器近战距离、伤害或冷却。
- `HHHumanoidAnimationDriver` 对应优先匹配武器动作片段，找不到时再匹配通用 attack 片段；没有可用原生片段时继续走程序化动作。
- 本地与远程人形均使用同一动作分类。确认受击会打断本地攻击；远程动作采用 `hit > attack > move/idle` 优先级，低优先级攻击事件不会覆盖正在播放的受击反馈。


### 武器目录类型

- `item_definitions.weapon_type` 是武器的正式数据字段，非武器必须为空；允许 `sword/spear/bow/staff/dagger/axe/hammer/focus`。武器动作分类由 WorldServer 根据角色服务端装备快照中的该字段决定，不再以物品名称作为主判断依据。
- 背包目录、当前背包、当前装备和世界入场快照统一返回 `weapon_type`。旧快照或旧数据缺失该字段时保留名称回退逻辑，以便分阶段部署。
- `spear` 使用突刺、`bow` 使用射击、`staff/focus` 使用施法、`axe/hammer` 使用重型挥击、`sword/dagger` 使用斩击动作；动画缺失时回退通用或程序化动作。

- 箭矢位置通过 20Hz 世界实体快照同步，客户端只创建/插值箭矢外观；命中、伤害、怪物死亡、经验/修为、魂魄吸收和掉落均由 WorldServer 结算。命中后服务器向附近观察者发送仅用于表现的 `visual_only` 战斗事件，观察者不参与奖励或伤害结算。目标死亡、消失、射手离线或箭矢超时都会移除投射物。
- 法杖/法器法术系统第一阶段：新增服务器白名单法术定义模块 `simulation/spell_combat.hpp`，首个启用法术为火球术（ID `fireball`）：灵力消耗18、施法时间350ms、冷却1800ms、射程20m、弹速16m/s、弹体生命周期1.8s、伤害倍率1.25x。客户端只能请求法术ID，不能提交伤害、消耗、射程或弹速等战斗参数。
- 法术规则测试覆盖未知法术ID、资源不足、非法资源消耗、NaN射程、无效弹速和防御穿透边界；已注册为独立CTest目标。
- 角色现有 `character_attributes.mana/max_mana` 已贯通 WorldServer 入场：服务端从会话战斗属性接口读取当前灵力和上限，校验非负及上限边界，并将资源写入本地玩家状态、欢迎包、玩家加入事件和实体快照。
- WorldServer 周期快照、断线保存和正常关闭都会提交当前 `mana`；后端仅接受受信任节点的会话快照，并使用 `LEAST(mana, max_mana)` 保护数据库资源上限。旧客户端/旧节点不提交 mana 时仍兼容原有快照行为。
- 火球术已接入第一条完整服务器战斗链路：协议类型22为 `SpellCastCommand`；客户端按 Q 请求当前锁定目标或20米内最近目标，客户端只提交法术ID和目标ID。WorldServer 校验存活状态、法杖/法器装备、白名单法术、灵力、冷却、目标有效性与射程，施法开始预扣18灵力，350ms后再次验证目标与射程并生成服务器权威火球。
- 火球弹体沿服务器世界tick推进，弹速16m/s、生命周期1.8s，复用已有 swept-circle 投射物碰撞和服务端伤害结算；命中、目标死亡、奖励/掉落仍由 WorldServer 决定。20Hz快照同步火球位置和类型，Godot客户端按类型绘制低面数发光球体，并显示施法/灵力反馈。
- 施法完成前目标消失、玩家倒地、目标离开射程或投射物容量不足时，服务器返还预扣灵力；玩家在施法中断线/正常关闭会话时，最终保存也会返还预扣灵力。冷却仍保留，避免取消请求反复试探。当前没有场景遮挡检测，也不因移动自动打断施法；这两项留待碰撞世界和施法动作完善后再做。
- 已扩展法术目录测试，验证火球关键平衡参数；尚未在本环境执行CMake/CTest或Godot运行测试，需由仓库CI/本地构建确认。
- 在线资源一致性第一道保护已完成：普通角色背包消耗品接口现在检查 connecting/active/saving 会话，角色处于世界会话时返回 HTTP 409，禁止绕过 WorldServer 直接修改在线 health/mana；世界入场票据兑换与角色资源事务通过角色行锁串行化，避免进入世界和使用道具同时发生的竞态。离开世界后仍可正常使用消耗品。
- 当前这是防止数据覆盖的安全闸，不代表在线回蓝已开放。Godot背包在世界会话中会禁用消耗品按钮并说明需先离开世界；HTTP 409也有单独提示。
- 在线消耗品后端基础已铺设：新增 `POST /api/v1/servers/inventory/use`，只接受WorldServer密钥、节点标识、活动session、角色ID、请求ID、物品ID和数量；后端在同一数据库事务中锁定活动session/角色、幂等校验、扣除背包物品并更新health/mana，返回最终资源值。普通玩家API仍禁止在线直改。
- 下一步将WorldServer消耗品命令接入 ENet 和后台任务队列：客户端只发送物品ID/数量/请求ID，WorldServer向该可信接口提交会话身份；成功后在主线程应用后端返回的health/mana，再通过快照同步。请求需幂等，网络失败不能先扣本地资源。


### 在线消耗品 ENet 结算链路

- 协议新增 UseConsumableCommand（类型23）。Godot客户端只发送物品ID、数量和随机请求UUID；会话ID、角色ID由WorldServer从已认证玩家状态中读取，客户端不能伪造身份。
- WorldServer 使用独立单线程消耗品队列执行 HTTP 请求，主世界循环不等待网络；每个会话同一时间只允许一笔消耗品请求，队列容量有限。
- 请求使用 X-World-Server-Key 与 X-World-Server-Node 认证头，调用后端 POST /api/v1/servers/inventory/use。后端在事务中核验活动会话、锁定角色、幂等扣除物品并返回最终 health/mana。
- 只有主线程收到成功结果且仍找到相同 session/character 时，才更新 WorldServer 玩家资源并发送 CombatEvent(action=consumable_use)；失败不提前扣本地资源。Godot同步生命/灵力HUD并刷新背包。
- HTTP超时或服务端错误时，WorldServer使用同一 request UUID 最多重试三次；后端幂等重复请求返回当前权威资源值，避免重复扣物品。
- 消耗品结算期间，WorldServer跳过该会话的周期快照，避免旧内存资源值覆盖正在结算的数据库结果。

### 冰系怪物攻击与玩家减速（第二阶段）

- 怪物目录按 ID/名称识别冰系游魂（`frost_soul`、`ice_soul`、冰魂/冰系游魂），使用远程攻击风格 `frost_bolt`；蓄力820ms、恢复720ms、冷却2400ms，并沿用远程游魂的风筝距离。
- 冰系游魂使用服务器计算后的远程有效射程；移动风筝距离和攻击命中判定共用该射程，避免只在近战基础射程内才会真正命中。\n- 冰系游魂命中玩家后，服务器施加移动速度倍率0.70、持续2200ms的减速。只改变玩家水平移动步长，不改变跳跃、伤害、攻击速度或客户端输入速率。

### 火球术灼烧与周期伤害（第一阶段）

- 火球术命中未死亡怪物时附加灼烧：持续3秒，每1秒结算一次；每跳伤害为施法者攻击力的20%，最低1点。冰锥术不附加灼烧。
- 周期伤害由WorldServer单调时钟驱动，客户端不能提交持续时间、间隔或伤害参数；按剩余跳数而非单纯墙钟到期来保证结算次数，20Hz世界循环每次最多结算一跳，服务器卡顿不会一次性补发多跳，也不会丢失最后一跳。
- 同类灼烧重复命中时不叠加多份效果：延长结束时间，保留较高的每跳伤害，并沿用较短的合法结算间隔。
- 灼烧击杀沿用施加灼烧的角色作为击杀归属；角色仍在线时正常发放经验/修为、冥界魂魄经验与掉落/吸收。怪物死亡或重生会清理灼烧状态。
- 新增周期伤害纯逻辑测试，覆盖触发时机、刷新、不叠加、过期、延迟帧不爆发补跳及非法参数。尚未执行CMake构建、CTest或Godot实机验证。
- Godot客户端在怪物脚下显示橙红色灼烧环；命中事件启动/刷新表现计时，持续伤害事件补充跳伤数字，死亡时移除状态环。表现层不参与伤害判定。


### 毒系游魂与中毒状态（第一阶段）

### 体质抗性（第一阶段）

- WorldServer从登录时的权威 `combat-stats` 读取角色体质（constitution）与元气/生命资质（vitality）；两项都包含已装备物品提供的属性加成，不依赖客户端提交值。
- 负面状态抗性基点公式：`min(5000, constitution × 20 + vitality × 10)`，上限50%，不会完全免疫状态。
- 抗性同时降低毒素每跳伤害与中毒持续时间，也缩短冰魄游魂的减速持续时间；中毒最短保留1秒，冰霜减速最短保留0.5秒，避免状态被高属性完全抵消。
- 战斗事件返回本次生效的抗性基点，客户端仅展示抗性反馈；最终伤害、持续时间和生命扣除均由服务器计算。
- 新增纯逻辑测试覆盖抗性计算、50%封顶、伤害下限、持续时间下限与非法参数。尚未执行C++构建、CTest或Godot解析/实机验证。
