# 世界地图与地形系统方案

更新：2026-11-20
适用项目：HongHuangWorld Godot 4 客户端

## 1. 当前真实实现（不是目标设计）

- `Client/HongHuangClient/scripts/world_scene.gd::_build_terrain()` 在运行时创建一块 `PlaneMesh`，尺寸为 240m × 240m。
- 同时创建尺寸 240m × 0.2m × 240m 的 `BoxShape3D` 地面碰撞体。
- 青云界和酆都目前共用这块平地，只改变地面颜色；酆都另外用程序化节点创建忘川河、河岸、奈何桥、石碑等局部场景物件。
- 目前没有 heightmap、真实高低起伏、地形分块、远景地形、地形 LOD 或地形流式加载。
- 当前雷达半径为 55m。它以玩家为中心，把世界坐标差映射到雷达像素；玩家移动后标记位置动态变化。它不是世界地图，也不会加载地形。
- 当前区域名由客户端坐标范围规则判断；探索点、NPC、怪物位置来自服务端/数据库数据。区域名规则不应长期成为权威地图边界。

## 2. 世界尺度建议

采用“世界（World）—区域（Region）—地形块（Terrain Tile）—兴趣点（POI）”四级结构：

- **World**：酆都、青云界、万妖界等独立游戏世界，拥有独立坐标空间和世界规则。
- **Region**：可独立进入、加载、维护的玩法区域，例如酆都荒原、忘川河畔、青云山门、百兽岭。
- **Terrain Tile**：地形编辑/加载单元，建议第一阶段按 256m 或 512m 边长规划；具体采用值由 Terrain3D 的 region 配置、碰撞半径和实测性能决定。
- **POI**：NPC、怪物刷新点、探索点、传送点、建筑、采集点等，保存于服务端权威数据中。

第一阶段建议：
- 每个可玩 Region 先按约 1km × 1km 的空间预算设计，不代表所有区域必须一次性全部加载。
- 先把现有 240m 测试场景扩展为一个 512m 或 1km 的可玩样板区域，确认移动、碰撞、视距、怪物刷新和地形性能后再扩展。
- 世界不设置一个无限大的单一平面；通过多个 Region 和地形块组合世界。
- 大地图显示已配置的区域/道路/地标；未制作的区域明确标记为未开放，不用空白地面假装已经有内容。

以上是规划尺寸，不是已经部署的地图边界。当前服务端出生点、怪物刷新点和探索点主要集中在约几十米范围，尚不能据此认定整个世界的真实边界。

## 3. 地形插件决策：采用 Terrain3D，分阶段接入

推荐插件：TokisanGames/Terrain3D（MIT）。

用途：
- 编辑器内雕刻山体、山谷、坡地和河床。
- 导入/编辑 heightmap。
- 地表多材质绘制与纹理混合。
- 地形网格 LOD 和 foliage instancing。
- 地形高度查询与碰撞，为角色移动、道路、建筑放置提供地表基础。

官方项目：
- https://github.com/TokisanGames/Terrain3D
- https://terrain3d.readthedocs.io/en/stable/
- https://terrain3d.readthedocs.io/en/stable/docs/installation.html
- https://terrain3d.readthedocs.io/en/stable/docs/platforms.html

兼容性约束：
- 项目美术方向文档当前写明 Godot 4.6；正式导入前必须在开发环境锁定精确 Godot 版本，并下载对应版本/平台的 Terrain3D GDExtension 二进制。
- 不把其他 Godot 小版本或操作系统的 GDExtension 二进制混用。
- Terrain3D 官方说明移动端、macOS、D3D12、Web 有额外平台限制；本项目先以 Windows/Linux 桌面客户端验证，再评估移动端。
- Asset Store 页面可能标记某个发布包为不稳定版本；以官方 GitHub Release 的版本说明、二进制文件和平台文档为准，不能盲目追最新版。
- Terrain3D 只负责地形渲染、编辑、地形数据和相关碰撞；它不负责 MMO 世界分区、玩家会话、怪物刷怪、兴趣点权限、区域切换或服务端权威。

## 4. 动态世界与流式加载由项目自己实现

Terrain3D 的 LOD/clipmap 不是完整 MMO 地图流式系统。项目需另建 WorldRegionStreamer：

1. 读取服务端/客户端世界目录中已开放的 Region 元数据。
2. 以玩家所在 Region 为中心，计算需要加载的相邻地形块。
3. 进入加载半径时加载地形、道路、建筑和静态环境资产。
4. 离开卸载半径时回收远处环境节点；保存/同步规则由服务端负责。
5. 怪物/NPC/玩家实体仍由 WorldServer 权威状态驱动，不能因为客户端卸载地形就删除服务端实体。
6. 加载与卸载采用不同距离阈值，避免玩家在边界来回移动造成抖动。
7. 区域切换、出生点、传送点、导航和大地图共用同一份 Region/POI 元数据。

建议先做单 Region 可运行闭环，再做相邻 Region 无缝加载；不先实现大规模无限地图。

## 5. 服务端地图元数据要求

现有数据库已经有：
- `world_exploration_points`：world_id、region_id、名称、描述、位置、交互半径等。
- `world_monster_spawn_points`：world_id、spawn_x、spawn_z、刷怪规则等。
- NPC 定义也包含世界坐标。

后续需要补齐统一的 Region/World 地图元数据：
- region_id、world_id、名称、描述、启用状态。
- 世界坐标边界（min_x/max_x/min_z/max_z）和可选多边形边界。
- 地形资源标识、heightmap/材质配置版本、地形块坐标。
- 出生点、传送点、道路/地标引用。
- 进入等级/种族/任务条件（如玩法设计需要）。
- 地图发现/探索可见性策略。

坐标边界和区域归属由服务端数据定义。客户端可以缓存和渲染，但不能单独决定玩家是否允许进入某区域。

## 6. 现有功能迁移约束

- 保留现有服务端世界坐标，不因换地形插件随意移动 NPC、刷怪点和探索点。
- 先制作地形，再按地形高度校准 POI 的 Y 坐标；X/Z 坐标保持稳定。
- 玩家移动碰撞、怪物寻路、攻击距离和服务端战斗判定不依赖美术网格。
- 道路、桥梁、建筑等可通行区域必须有清晰碰撞；地形碰撞和建筑碰撞分层管理。
- 雷达继续作为独立 HUD，不与 Terrain3D 耦合；以后大地图直接读取 Region/POI 元数据。
- 迁移阶段保留旧 PlaneMesh 作为开发 fallback；Terrain3D 场景加载、碰撞和高度查询验证通过后再移除。

## 7. 分阶段实施

### T0：版本与插件验证
- 锁定 Godot 4.6 的精确补丁版本和导出平台。
- 添加 Terrain3D 对应版本的插件文件及许可证/版本记录。
- 建立独立 Terrain3D 测试场景，不先替换正式世界。
- 验证编辑器启动、地形绘制、heightmap 导入、运行时高度查询、角色碰撞和导出构建。

### T1：酆都样板地形
- 创建首个 512m 或 1km 样板区域。
- 制作地势、忘川河谷、奈何桥周边、鬼门关入口和可行走道路。
- 将现有服务端 POI 坐标投放到地形上，校准 Y 高度。
- 验证玩家移动、怪物移动、导航距离、地形碰撞与雷达显示。

### T2：青云界样板地形
- 创建山门、石径、松林、山谷和百兽岭地形。
- 复用相同地形资产规范和地形加载接口。
- 地图内容以可商用免费资产/原创资产为主，保留来源与许可记录。

### T3：区域流式加载与大地图
- 增加 RegionStreamer、加载/卸载阈值和资源缓存。
- 大地图显示区域边界、道路、已发现地点和探索进度。
- 完成相邻区域切换和传送流程后，再扩展更大世界。

## 8. 验收标准

- 不再把 240m 平地当作已完成世界地图。
- 玩家在起伏地形上移动、跳跃、碰撞正常，脚底高度与 Terrain3D 一致。
- NPC、怪物、探索点 X/Z 与现有服务端权威数据一致，Y 高度与地形正确贴合。
- 地形加载/卸载不删除或重置服务端权威实体。
- 远距离地形有 LOD，近距离碰撞可用；进入/退出区域边界不闪烁、不重复加载。
- 桌面导出构建包含正确平台的 GDExtension；缺少插件时开发 fallback 有明确提示。
- 在目标机器实测帧率、内存、加载时间后再决定单 Region 尺寸和同时驻留块数量。

## 9. 地图坐标适配层（已开始实施）

客户端新增 `scripts/world_map_projection.gd`，作为与渲染器无关的 X/Z 坐标投影工具：

- `world_to_map`：世界坐标投影到地图 UI 坐标。
- `map_to_world`：地图 UI 坐标反算回世界坐标，供未来大地图点击寻路/选点使用。
- `is_inside_circle`：统一雷达圆形范围命中判断。
- `world_xz_in_bounds`：按世界坐标边界判断点是否落在区域矩形范围内。

当前小地图已经改为调用该投影工具。未来全屏大地图应复用同一工具，并通过不同的 origin / scale 参数实现缩放和平移；地图 UI 不直接读取 Terrain3D 节点或 heightmap。这样替换地形渲染器不会改变地图标记、导航和 POI 坐标。

后续扩展时，投影层还应由独立的 MapView 状态提供缩放、平移和视口裁剪参数；交互命中必须使用同一套正反变换，不能另写一套近似坐标公式。

## 10. 冥界新增区域：血海（规划纳入酆都世界）

血海是冥界中的独立 Region，不另建一个平行世界，也不把它仅作为忘川河的红色材质版本。

建议区域标识：`fengdu_blood_sea`；所属世界：`underworld_fengdu`。正式世界坐标边界、面积和地形 tile 数量待区域地图数据确定后配置，不在客户端猜测边界。

### 主题与地貌

- 主体为广阔的暗红/黑红色血海，海面有缓慢潮汐、局部漩涡和灵魂残光。
- 海岸以黑色礁岸、血色滩涂、枯骨浅滩和断裂石碑构成。
- 海面分布少量浮岛、沉没祭坛和残破古战场遗迹，作为可探索 POI。
- 远景以血雾、暗红天幕和若隐若现的巨大轮廓建立纵深；不使用无边界平面假装无限海域。

### 玩法定位

- 血海应是中高危险探索区域，不作为新玩家出生点。
- 设计血潮涨落、漩涡危险区、血雾视野压制和灵魂侵蚀等区域机制；具体数值由玩法平衡阶段决定。
- 可布置血海游魂、沉尸怨灵、血兽等敌对生态，以及稀有魂材/血属性资源。
- 跨越海域需要明确的通行方式（渡魂舟、魂桥、特殊能力或任务解锁），避免玩家直接在海面无条件行走。
- 区域探索分层：海岸可探索、浅海危险带、深海禁区；发现 POI 后才在大地图逐步显示。

### 地图与服务端约束

- Region 元数据、进入条件、危险等级和边界由服务端权威定义；客户端只负责展示。
- 血海地形先以独立 Terrain3D 测试场景制作，不立即替换正式酆都场景。
- 血海水面/潮汐/雾效属于环境表现；危险区、移动限制、资源刷新和怪物行为必须由服务端规则验证。
- 先完成海岸样板区和一个可交互 POI，再扩展整片海域；不提前声称血海已有确定面积或完整地图。
