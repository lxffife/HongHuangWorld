# 酆都天城 3D 灰盒原型

状态：独立 3D 灰盒漫游 / 城市模块化第一阶段
场景：`scenes/experiments/FengduCapitalGreybox.tscn`
城市生成器：`scripts/experiments/fengdu_capital_greybox.gd`
可复用模块场景：`scenes/experiments/FengduCityModule.tscn`
可复用模块脚本：`scripts/experiments/fengdu_city_module.gd`
NPC 对话面板：`scripts/experiments/npc_dialogue_panel.gd`
NPC 状态机：`scripts/experiments/npc_behavior_controller.gd`
本地任务管理：`scripts/experiments/fengdu_quest_manager.gd`

## 1. 本阶段目标

将酆都从平面规划图推进为可行走的三维空间，并开始建立可复用的城市模块。该场景是独立实验，不替换线上世界场景，不改动正式玩家网络控制器，也不改变服务端世界边界。

## 2. 灰盒尺度

| 项目 | 当前原型尺寸 |
|---|---:|
| 城墙外轮廓宽度 | 1,900 m |
| 城墙外轮廓纵深 | 1,475 m |
| 护城河宽度 | 60 m |
| 城墙高度 | 54 m |
| 城墙厚度 | 18 m |
| 城门净开口目标 | 112 m |
| 南北主御道宽度 | 52 m |
| 东西主干道宽度 | 52 m |
| 城区位置映射 | 城市规划示意坐标 × 2.5 |

以上是本次灰盒的临时游戏尺度，不是最终世界设定的不可变数值。为了给道路留出通行空间，鬼籍司、功过司、巡城司和轮回司在 3D 灰盒中有少量局部布局偏移；平面规划目录本身未被改写。未来还要根据玩家步速、建筑内部空间、视距、性能与服务器分区进一步校准。

## 3. 城市结构

- 环城护城河、四面城墙、四角及沿墙瞭望塔、墙垛。
- 北天门、南幽门、东玄门、西冥门门楼、桥面和方向标识。
- 南北主御道、东西主干道、城区连接街、鬼市与居民区内部巷道。
- 皇城、十王府、判官司、鬼籍司、功过司、巡城司、轮回司、万魂鬼市、万家魂坊。
- 阴兵大营、引魂驿站。
- 宫殿主殿、上层殿、侧殿、宫苑平台；官署侧院；鬼市多排商铺与廊架；魂坊住宅与巷道；军营营房和操练场；驿站候车平台。
- 皇城主殿改为前向敞开的可进入式壳体：左右墙、后墙、前柱、内柱、御座台与地面碰撞分离，玩家可以从正面进入主殿内部。
- 魂坊六栋民居改为开放门洞结构，包含地面、侧墙、后墙、门柱、门楣、屋顶和简易床榻/桌案占位，可从巷道进入室内。
- 鬼市增加拍卖广场、拍卖台、环形立柱、地下黑市入口楼梯和门楼占位。

## 4. 模块化和场景对象

`FengduCityModule.tscn` 是可复用模块场景，通过配置字典选择模块类型：

| 模块类型 | 用途 |
|---|---|
| district | 宫殿、官署、鬼市、居民坊、军营和驿站 |
| watchtower | 城墙角楼与沿墙瞭望塔 |
| gatehouse | 城门楼体块 |
| guard | 阴兵守卫和简易往返巡逻 |
| citizen | 商贩、居民、文吏和引魂使占位 NPC |
| special_character | 黑白无常、牛头马面等有独立外形、路点和交互数据的阴司重要角色 |

NPC 行为状态由 `npc_behavior_controller.gd` 统一管理；对话 UI 由 `npc_dialogue_panel.gd` 统一呈现。角色专属话题由 `interaction_type` 数据选择，避免在城市生成器里堆叠角色对话分支。四名阴司角色通过 `quest_id` 关联差事定义，任务系统与对话 UI 分离。

每个城区模块可独立生成碰撞体、屋顶、建筑群、名称牌和交互触发区。建筑仍是基础几何体，不是最终美术模型。

## 5. NPC 与城区交互

当前场景已加入：
- 南北城门守卫、东西城门守卫、皇城、鬼市和魂坊附近的阴兵占位模型。
- 12 座可复用瞭望塔、沿墙墙垛，以及 10 名阴兵占位守卫；守卫沿短距离往返移动。
- 13 名鬼市商贩、魂坊居民、鬼籍书吏、功过司文吏、巡城司值守、引魂使等占位 NPC。
- 新增四名具名阴司角色：黑无常·范无救、白无常·谢必安、牛头将军、马面将军。黑白无常位于南门内侧引魂路段，负责拘魂与接引主题；牛头马面驻守南幽门内侧，承担城门守卫主题。
- 四名角色采用独立低多边形组合模型：黑白无常有黑/白官袍、高帽、帽面题字与拘魂簿；牛头有牛角与兽首，马面有马首、长吻与耳形轮廓；牛头马面配有兵器占位。
- 四名角色各自拥有名称牌、状态牌、独立交互触发区和说明数据；按 E 打开统一 NPC 对话面板，可查看职责、开放条件并选择角色专属话题或领取本地原型差事。黑白无常配置拘魂/接引行为档案，牛头马面配置守门/巡防行为档案；任务不改变魂魄状态，也不授予通行权限。
- 四名角色拥有轻量待机呼吸反馈；状态牌分别显示“拘魂巡查中”“接引新魂中”“南门盘查中”“南门巡防中”，并沿各自短距离路点移动。进入交互范围后切换“交涉中”并暂停巡逻，离开后恢复巡逻状态。角色模型与触发器分离，呼吸动画只作用于袍身视觉节点，不影响交互碰撞。
- 通用 `npc_behavior_controller.gd` 状态机供守卫、居民和重要角色复用，当前状态包括待命、巡逻、交涉、警戒、追击和归位；本阶段实际接入待命/巡逻/交涉三类本地状态，其余状态作为后续战斗与警戒行为的扩展入口。
- 新增 `fengdu_quest_manager.gd` 与 `fengdu_quest_journal.gd`：四名阴司角色分别提供一项两阶段差事。六项基础/分支差事配置固定冥币奖励；目标全部完成时由经济管理器自动结算，任务簿展示奖励金额与到账状态。马面可重复巡防差事每轮完成都会增加独立结算序号，防止同一轮重复发奖。玩家可在角色对话中领取差事，随后与指定官署/城区交互推进当前目标；任务簿显示委托人、任务说明、逐项目标、部分计数、当前状态和奖励预览；可切换追踪目标或放弃进行中的差事。右上角常驻追踪 HUD 展示当前目标和计数。
- 新增 `fengdu_story_state.gd` 独立管理剧情旗标、玩家选择与阵营声望，不把分支判断写入 UI。白无常的「新魂引登记」完成后，玩家可选择「按章登记」或「先安抚亡魂」：前者记录 `supported_yin_official_order` 并提升阴司官署声望，后者记录 `protected_new_soul` 并提升新魂群体声望；选择会改变白无常后续对话，并分别解锁「官署魂籍复核」或「未了心愿寻访」两阶段后续差事。未满足剧情旗标的分支任务不会显示在任务簿中，也不能领取。选择与声望只记录本地剧情状态，不发放物品、货币或正式权限。任务状态包含待领取、进行中、已完成待结算、失败和放弃；可配置前置任务与是否可重复接取。目标数据支持 interact、collect、defeat、escort、investigate、deliver 六种事件类型，并可设置累计次数。当前场景交互会驱动 interact / investigate / deliver 三类目标，马面的巡防回报配置为可重复差事；其他事件由未来战斗、采集和护送系统调用统一事件接口。重复事件会按目标要求累计，不会越过当前目标。奖励只显示预览，不发放货币、属性、物品或通行权限。

| 委托角色 | 差事 | 目标顺序 |
|---|---|---|
| 黑无常 | 拘魂文牒核验 | 鬼籍司 → 功过司 |
| 白无常 | 新魂引登记 | 引魂驿站 → 轮回司 |
| 白无常（官署分支） | 官署魂籍复核 | 鬼籍司 → 功过司 |
| 白无常（安抚分支） | 未了心愿寻访 | 引魂驿站 → 轮回司 |
| 牛头 | 南幽门巡检记录 | 鬼籍司 → 巡城司 |
| 马面 | 南门巡防回报（可重复） | 巡城司 → 万魂鬼市 |
- 阴兵巡逻由正弦摆动改为数据驱动的多点循环路线；城门、皇城、鬼市、魂坊守卫分别配置局部巡逻点。
- 3 名鬼市商贩和 3 名魂坊居民配置低速日常活动路线；其余书吏/引魂使暂时驻守。
- 鬼市 12 个摊位分别配置靠近触发区，按 E 查看摊位类别、管理方和当前原型说明；另有拍卖广场与地下黑市入口说明触发点。
- 11 个城区入口触发区；进入城区入口附近时，HUD 显示目标名称，按 E 打开统一对话面板。面板包含身份标题、主管信息、说明文本、话题选项和关闭操作；选择话题只展示本地回应，不执行交易、任务或权限变更。
- 第三人称漫游相机、城内道路灯柱与中央广场占位。

NPC 仍没有完整寻路、战斗、经济、任务对话树、持久化身份或服务端同步。当前差事、剧情状态、冥币钱包、城主府库银、任务托管与公共委托仅在本次场景运行期间保存在内存中，不能作为正式任务、奖励、声望或经济系统。城区触发区也只是客户端原型提示，不能作为服务端权限依据。

## 6. 城市货币与公共任务大厅（本地原型）

酆都城加入独立的本地经济原型，货币统一称为**冥币**。任务大厅位于城西公共事务街区（灰盒坐标约 X=-720、Z=0），靠近大厅交互点按 E，或在任意位置按 T 打开。

### 货币与财政规则

| 项目 | 当前原型规则 |
|---|---:|
| 玩家初始演示余额 | 5,000 冥币 |
| 城主府初始演示库银 | 10,000 冥币 |
| 任务最低 / 最高悬赏 | 50 / 1,000,000 冥币 |
| 发布费 | 10 冥币 + 悬赏金额的 3%（向上取整） |
| 结算税 | 悬赏金额的 5%（向上取整） |
| 任务悬赏 | 发布时从发布者余额扣除并进入托管 |
| 取消规则 | 仅未被接取的任务可由发布者取消；退回悬赏，发布费不退 |
| 自接限制 | 发布者不能接取自己的任务 |
| 差事奖励 | 黑无常 120、白无常 150、分支差事 180、牛头 160、马面每轮 100 冥币 |

任务大厅展示玩家余额、城主府库银、托管悬赏和最近 8 笔交易流水。经济管理器记录差事奖励、任务发布费、悬赏托管、结算税收、退款和城主府示范悬赏拨款；每条流水包含玩家余额变化、城主府变化、托管变化、变更后余额与说明。任务大厅展示最近流水，便于核对资金去向。任务发布前会检查余额和文本长度；发布成功后悬赏进入托管，发布费进入城主府库银。接取者提交完成后，演示结算会从托管悬赏中扣除本金，向接取者支付扣税后的金额，税款进入城主府。已被接取的任务不能由发布者直接取消。

首次进入场景时，城主府会从库银中拨出两笔示范悬赏，分别来自鬼市灵材商和魂坊工匠，方便体验接取、完成和结算流程。玩家发布的委托也会进入同一公开列表。

### 当前边界

- 经济管理器与任务大厅 UI 独立于剧情任务管理器，但场景会将经济管理器注入差事管理器；普通差事完成后会自动发放冥币。
- 当前只有本地演示账户，重开场景会重置余额、财政、托管、任务和交易流水；没有账号绑定、数据库持久化、跨玩家同步或服务端权威校验。
- “提交完成”按钮是流程演示，不代表真实目标验收；正式版本必须由服务端根据任务目标、证据、时间和双方状态判定。
- 当前尚无玩家间直接转账、商店买卖、拍卖竞价、物品寄售、交易手续费和反洗钱/刷币风控。
- 发布费和税率目前是固定原型常量，不代表城主府已经具备可配置的正式财政管理后台。

## 7. 如何运行

1. 在 Godot 4 编辑器中打开 `Client/HongHuangClient/project.godot`。
2. 在文件系统中打开 `res://scenes/experiments/FengduCapitalGreybox.tscn`。
3. 使用“运行当前场景”（F6），不要将它设为项目主场景。
4. 首次点击场景窗口捕获鼠标。

控制：
- W/A/S/D：移动（对话面板打开时暂停角色水平移动）。
- 鼠标：观察方向（第三人称跟随视角）。
- Shift：奔跑。
- Space：跳跃。
- E：与当前附近 NPC / 城区 / 交互点交谈或查看；再次按 E 或 Esc 关闭对话面板。
- J：打开/关闭阴司差事簿；在任务簿中可切换追踪目标或放弃进行中的差事；右上角显示当前追踪目标。
- T：打开/关闭酆都公共任务大厅；可发布公开委托、接取他人悬赏、提交完成、取消尚未被接取的本人委托，并查看冥币余额与城主府库银。
- 对话、任务簿或任务大厅打开时暂停玩家水平移动。
- Esc：释放鼠标；点击窗口重新捕获。

## 8. 当前限制

- 这是单机本地灰盒，不连接玩家身份、聊天、游戏世界服务或服务器权威移动。
- 还没有 NavMesh、真正的避障寻路与完整 NPC 日程；当前巡逻和居民活动使用预设局部路点循环，不会绕开动态障碍，也不具备拥堵处理。
- 宫殿主殿和魂坊住宅目前是可进入的基础壳体与少量家具占位，侧殿/官署/商铺内部仍未全部开放；拍卖和黑市目前只有空间与说明交互，不含竞价、库存、支付、地下场景传送或交易。
- NPC 与四名阴司重要角色均为程序化低多边形占位模型，不是最终美术资产；角色状态机已预留待命、巡逻、交涉、警戒、追击和归位状态，但警戒/追击/归位尚未接入实际感知或战斗逻辑。对话面板具备本地话题选择和回应，四名重要角色可领取两阶段差事；任务管理器已预留前置条件、可重复任务、失败/放弃、追踪与六类目标事件接口；剧情状态支持旗标、二选一分支和阵营声望原型，当前均只在内存中，没有持久化、真实拘魂/战斗技能或服务端同步。
- 城区是基础体块与局部街巷，尚无完整建筑内部、精细屋顶、材质贴图、真实水体和生活动线。
- 护城河目前是静态水面，不具备水体物理和游泳机制。
- 尚未完成 Godot 编辑器解析、运行和性能实测；必须在本地 Godot 4 编辑器中运行当前场景后，才能确认运行时结果。
- 当前项目未锁定确切 Godot 4 小版本；不要在未核实版本兼容性前引入 Terrain3D 等外部插件。

## 9. 下一轮验收重点

1. 从南门步行进入，检查门洞、桥面、城墙碰撞和守卫位置。
2. 沿中轴道路前进，确认皇城远景可读、道路与建筑没有穿插。
3. 逐一走到九大功能区，测试 E 键信息提示与触发范围。
4. 从正面进入皇城主殿，确认门洞宽度、内柱、御座台和碰撞边界合理。
5. 从魂坊巷道进入至少两栋民居，检查门洞、室内家具和屋顶碰撞。
6. 逐个靠近鬼市 12 个摊位，按 E 检查摊位说明；检查拍卖广场与地下黑市入口的位置。
7. 与黑白无常、牛头马面分别保持近距离，按 E 查看角色身份、职责和说明；观察四名角色的外观是否容易区分。
8. 观察城门、皇城、鬼市、魂坊守卫是否沿预设路点循环，商贩、坊民和四名重要角色是否按各自速度活动。
9. 记录南门到皇城、南门到鬼市的实际步行时间，按体验调整城市比例。
10. 完成黑白无常、牛头和马面的差事，检查任务簿中的冥币奖励与钱包到账；重复完成马面巡防差事，确认每轮只结算一次。
11. 在公共任务大厅检查初始两条城中悬赏；发布一条自定义委托，验证发布费、托管余额、不可自接、取消退款和完成结算税款；检查最近交易流水中每笔变化；重开场景确认当前原型数据会重置。
