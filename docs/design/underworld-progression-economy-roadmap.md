# 洪荒世界：东方修行、冥界神通与双轨经济系统开发计划

> 状态：已确认设计方向；按阶段实施。  
> 目标分支：`feature/p0-foundation`  
> 设计原则：服务器权威、数据驱动、先闭环后扩容、兼容现有角色与战斗数据。

## 1. 产品目标

把角色成长从单一“学法术、打怪”扩展为完整的洪荒修行生活：

- 每个新角色出生即拥有免费的通用基础攻击能力，不需要法杖、不需要先购买技能。
- 怪物战斗、任务、探索产生货币、材料、装备和传承线索。
- 玩家用所得资源购买、学习或制作神通、兵器、丹药、符箓、阵法与法宝。
- NPC 官方商铺提供稳定、可预期的基础供给；玩家商铺形成自由交易和专业分工。
- 战斗者、炼丹师、制符师、阵法师、锻造师、商人都能成为可持续的成长方向。

核心循环：

**战斗／探索／生产 → 获得货币与材料 → 学习神通或购买/制作装备 → 挑战更高风险区域 → 形成玩家交易与专业分工。**

## 2. 战斗与技能体系

### 2.1 免费通用基础攻击

基础攻击是所有玩家的默认战斗动作，不占技能学习名额、不收取购买费用、不依赖法杖。

- 徒手：掌击、拳劲、指诀或基础真气冲击。
- 装备兵器后：普通攻击由服务器按当前武器类型决定动作、距离、攻击间隔和伤害。
- 剑、刀、枪、戟、弓、棍等各自拥有不同的攻击节奏与距离。
- 基础攻击不消耗冥石；是否消耗耐久、体力或其他资源另由装备规则控制。
- 客户端只发送攻击意图；目标、距离、冷却、伤害、武器合法性由世界服务器验证。

当前项目已经有鼠标左键普通攻击、装备攻击距离和服务端命中判定。本阶段应在现有基础上扩展武器差异，不重复造一套普通攻击系统。

### 2.2 技能分类

技能不是一排西方元素球。以道法、符箓、剑诀、法印、阵法、魂魄、雷法和法宝为表现体系。

| 类别 | 代表能力 | 定位 |
|---|---|---|
| 通用天地修行 | 五雷正法、剑气纵横、罡气护体、踏云步、金光护身、镇邪符、五行遁术、养气归元 | 所有符合修行条件的角色可学习 |
| 酆都冥司 | 鬼门锁链、镇魂钟、阴兵借道、冥司敕令 | 控制、镇压、召唤、防护 |
| 黄泉忘川 | 黄泉引路、忘川迷雾、三途弱水、业镜照魂 | 持续伤害、减益、侦测、辅助 |
| 十八层地狱 | 幽冥磷火、业火焚身、狱门镇压、罪业审判 | 爆发、持续伤害、惩罚、控制 |
| 幽冥血海 | 血神子、血海遁、血海滔天、业火红莲、阿修罗战意 | 近战爆发、分身、吸血、突进 |

后土娘娘为冥界最高主宰、冥河老祖统御血海，是本项目采用的世界观整合设定；不把它表述成所有古籍中完全一致的神谱。

### 2.3 施法与装备规则

- 不设“法杖”为施法前提，也不把法杖作为默认职业装备。
- 兵器：剑、刀、枪、戟、弓、棍等，主要决定普通攻击与武技。
- 法器：法剑、符箓、令牌、法印、法尺、铃、钟、令旗等，用于施法、镇压、召遣和布阵。
- 法宝：葫芦、宝镜、宝塔、幡、莲台、缚妖索等，提供主动能力、被动效果或技能形态变化。
- 徒手修行者也能通过掌法、指诀、罡气和真气施展能力。

### 2.4 技能栏与学习

保留现有 Q/R/T/Y/U/G/H 快捷键作为可配置技能栏，不把某个键永久绑定成某个技能。技能栏显示技能图标、名称、资源消耗、冷却和可用状态。

技能学习来源：
1. 官方藏经阁、冥司传功殿、各传承 NPC。
2. 任务、首领、秘境、探索与世界事件。
3. 玩家交易的技能典籍、传承信物、符箓或法宝。
4. 师徒/宗门传授（后续阶段）。

购买不等于立即无条件掌握。学习时检查角色境界、属性、传承、前置技能、道具和货币；部分技能需要消耗典籍或传承信物，学习成功后永久记录到角色技能库。

## 3. 货币与掉落经济

货币建议：

| 货币 | 来源 | 主要用途 |
|---|---|---|
| 冥币（ghost_cash） | 普通怪物、任务、日常活动、出售杂物 | 基础药品、修理、常见消耗品 |
| 冥石 | 精英怪、首领、任务、探索和高风险区域 | 技能学习、装备、丹药、符箓、阵法 |
| 灵玉 | 稀有首领、赛季/世界活动、珍稀交易 | 高阶法宝、稀有典籍和高阶材料 |
| 传承信物 | 指定首领、秘境、传承任务 | 解锁流派、传承技能和高阶修行 |

经济约束：
- 普通怪物以冥币和常见材料为主；精英、首领提供更高价值的冥石、材料和信物。
- 掉落表由服务端控制，按怪物、等级、区域、稀有度配置。
- 组队奖励按有效贡献分配，不能靠重复请求或客户端伪造获得。
- 金币发放、购买、出售、交易必须使用服务端事务和幂等请求；禁止客户端直接修改余额。
- 记录货币来源与去向（money sink），监控单位时间产出、消耗、玩家余额分布和异常刷取。
- 首阶段只做铜钱、冥石两种可流通货币；灵玉与传承信物在后续内容阶段启用，避免早期经济过度复杂。

## 4. 商业体系

### 4.1 官方 NPC 商铺

官方商铺承担新手供给、价格锚点、材料回收和世界经济调节：

| 店铺 | 商品与服务 |
|---|---|
| 兵器铺 | 基础剑刀枪戟弓、武器升级材料、修理 |
| 丹药铺 | 疗伤、恢复、解毒、临时增益丹药 |
| 符箓铺 | 镇邪符、护身符、引魂符、攻击符 |
| 阵法铺 | 基础阵旗、阵盘、阵图、布阵材料 |
| 藏经阁/传承殿 | 通用神通、冥界传承、技能典籍 |
| 法器法宝阁 | 法剑、令牌、法印、钟、镜、葫芦、宝塔等 |
| 材料行 | 常见制作材料出售与回收 |

价格由服务端商品目录控制，可按区域、店铺等级、声望和活动调整。关键成长物品不能被低等级 NPC 商店无限量出售。

### 4.2 玩家商铺

分阶段开放：
- 第一阶段：玩家摊位/寄售行，出售背包中可交易的装备、材料、丹药、符箓、阵旗和典籍。
- 第二阶段：玩家店铺、店铺仓库、挂牌、租金、税费、经营等级。
- 第三阶段：雇佣 NPC、自动补货、跨区域商路、商会与店铺声望。

交易安全：
- 上架时锁定物品或转移到托管仓，避免重复出售。
- 买入与卖出使用原子事务；物品和货币必须同时成功或同时失败。
- 订单状态包括上架、成交、撤单、过期；每笔操作有唯一幂等 ID。
- 绑定物品、任务物品、已装备物品和不可交易传承物不得上架。
- 价格限制、手续费、税费和日志用于抑制洗钱、复制物品和异常交易。

## 5. 生产与专业成长

生产技能按后续内容开放：
- 锻造：兵器、防具、强化材料。
- 炼丹：恢复、解毒、突破辅助、短时增益。
- 制符：攻击、护身、镇邪、引魂符。
- 阵法：阵旗、阵盘、区域增益/减益、封锁和防御。
- 法宝炼制：稀有材料、传承图谱与高阶工艺。

生产必须依赖世界掉落、采集和玩家交易，形成材料需求；不要让 NPC 商店无限供应所有顶级成品。

## 6. 服务端数据与安全边界

所有经济与成长状态由服务端/后端权威保存。建议逐步形成以下数据实体（以现有 API 与数据库实际结构为准，先审计后迁移）：

- character_wallet：角色各类货币余额与版本。
- currency_ledger：货币增减流水，包含来源、去向、关联事件、幂等键。
- item_catalog：物品静态定义、类别、堆叠、绑定和交易规则。
- character_inventory：角色物品与数量。
- skill_catalog：技能定义、传承、学习条件、价格、效果参数。
- character_skills：已学习技能、熟练度和解锁来源。
- npc_shop_catalog：官方店铺、商品、价格、库存与刷新规则。
- player_market_listing：玩家挂单、托管物品、价格、状态、过期时间。
- market_transaction：买卖双方、物品、货币、税费和幂等记录。

以上为目标模型，不代表当前数据库已存在这些表。实施前必须检查已有钱包、背包、掉落、交易、迁移与后端 API，优先复用，禁止重复建表或破坏现有角色数据。

服务端必须验证：
- 攻击：武器、目标、距离、冷却、资源、伤害与贡献归属。
- 技能：已学习、传承资格、境界、冷却、资源、目标、距离和效果。
- 掉落：怪物死亡事件唯一性、有效贡献、掉落归属、拾取距离和拾取状态。
- 商店：价格、库存、余额、物品可交易性、容量和幂等。
- 玩家市场：挂单所有权、物品锁定、成交一致性、手续费和撤单状态。

## 7. 开发路线与交付顺序

### P0：现有系统审计与规则冻结
- 盘点普通攻击、武器类型、技能施放、技能熟练度、怪物掉落、背包、货币、商店/交易 API 和数据库。
- 标记已存在、部分存在、完全缺失的能力。
- 冻结物品 ID、技能 ID、货币 ID、协议字段和数据迁移策略。
- 验收：形成现状清单；无重复造轮子；保留现有角色与掉落数据。

### P1：东方技能与免费基础攻击（首个可玩闭环）
- 明确免费基础攻击与武器普攻的关系，保留鼠标左键连续攻击。
- 用东方神话主题替换火球术/冰锥术视觉和名称，逐步扩展为可配置技能目录。
- 第一批技能：幽冥磷火（持续伤害）、鬼门锁链（控制/拉拽）、镇邪符（标记/驱邪）、罡气护体（减伤）、踏云步（位移）。
- 技能学习、装备快捷栏和服务器权威验证。
- 验收：新角色无需购买即可普通攻击；技能未学习不能施放；服务端拒绝伪造技能、资源和冷却；至少 3 个技能有不同战斗机制。

### P2：铜钱/冥石与怪物奖励闭环
- 普通怪物冥币奖励；精英怪冥石与稀有材料；首领奖励按贡献分配。
- 背包拾取、余额同步、掉落日志与货币流水。
- 验收：怪物死亡只发放一次；断线重连不重复领钱；多人贡献按规则分配；客户端不能伪造余额。

### P3：官方 NPC 商铺
- 先做兵器铺、丹药铺、符箓铺、藏经阁四类。
- 商品列表、详情、购买确认、余额不足、背包满、库存不足和购买结果提示。
- 验收：购买扣币与发物品原子一致；失败不扣币不丢物；价格完全由服务端决定。

### P4：玩家交易行与摆摊
- 上架、浏览、筛选、购买、撤单、过期处理。
- 物品托管、货币托管、手续费、交易流水和防复制。
- 验收：并发购买同一订单最多成功一次；撤单与成交互斥；物品和货币不会凭空增减。

### P5：生产职业与阵法
- 炼丹、制符、锻造、阵法、材料采集和玩家专业成长。
- 验收：原料扣除与成品生成原子化；配方解锁有条件；产出与经济监控可追踪。

### P6：冥界四大传承与内容扩展
- 酆都冥司、黄泉忘川、十八层地狱、幽冥血海专属技能树、师门任务、首领掉落和传承信物。
- 后土冥司与冥河血海形成世界势力关系。
- 验收：四条路线在技能机制、资源循环和战斗定位上有区别，不只是技能改名。

## 8. 当前开发策略

1. 不暂停整个游戏开发；优先做可玩的垂直切片。
2. 不一次性开发完整拍卖行、商会、炼丹、阵法和全部技能；按 P0→P1→P2 顺序交付。
3. 任何数据库迁移先审计已有表和 API，保持向前兼容，不清理玩家数据。
4. 每批修改后做代码级检查、协议/数据契约检查；可用时运行 Godot 脚本校验和 C++ 构建。
5. 不宣称未实际运行的测试已通过；服务端 C++ 修改需要重新编译部署世界服务器。
6. 所有改动提交到 `feature/p0-foundation`，不自动合并 PR。

## 9. 本轮代码审计发现

- 客户端已存在鼠标左键普通攻击与按住连续攻击逻辑。
- 世界服务器已存在服务器权威的武器攻击距离、攻击冷却与命中判定。
- 世界服务器已存在法术施放、法术冷却、法力消耗、飞行投射物和命中熟练度。
- 当前法术定义仍是 `fireball` / `ice_bolt` 两个硬编码条目，且客户端 HUD、服务端熟练度校验和投射物表现存在多处硬编码。
- 世界服务器已从后端加载怪物掉落表，并通过后端接口加载/持久化地面掉落与拾取；怪物掉落当前以物品为主，铜钱/冥石奖励是否已经接入死亡结算仍需继续核对。
- 后端已经有统一货币定义、角色钱包、货币余额、不可变货币流水、货币发行策略和托管/兑换基础；冥界货币已定义为 ghost_cash（冥币）与 nether_stone（冥石）。不新建第二套钱包。
- 后端已有背包、装备、丹药使用、材料制作、掉落拾取与货币 API；原先没有官方 NPC 商铺目录/购买路由，也没有完整玩家寄售市场。
- 已新增酆都官方商铺目录与原子购买后端基础，商品包括现有兵器、丹药以及镇邪符/聚阴阵旗材料；物理 NPC 位置绑定、商铺 UI、技能学习商品和玩家市场仍待后续实现。
- 已把怪物死亡结算奖励扩展为按有效伤害贡献分配冥币；当前基础规则为每只怪物总冥币 `min(2000, 5 + 等级 × 3)`，等级达到 10 且属于每 5 级档位或精英/远古/首领类型时，另分配 1–5 枚冥石。奖励先写入世界服务器持久化 outbox，再由受信任世界服务器调用后端结算。
- 后端角色奖励事务现在同时处理经验、修为与货币入账；冥币/冥石进入现有 `currency_balances` 与不可变 `economy_ledger_entries`，并检查世界发行规则、单次上限和每日上限（冥币 50,000、冥石 200）。接近每日上限时只发放剩余额度，不会因此吞掉经验和修为。奖励事件使用独立幂等流水键，重试不会重复发放。
- 已新增迁移 `000074_underworld_monster_currency_rewards`，为酆都配置怪物击杀冥币/冥石发行策略；冥石允许通过精英怪掉落入账，但角色是否解锁冥石修炼用途仍由原有 unlock 规则决定。
- 客户端世界 HUD 新增冥币/冥石余额显示，每 15 秒同步一次，并在怪物奖励结算后刷新。
- 新增 C++ 贡献奖励分配测试目标，覆盖多人按伤害比例分配、整数余数稳定分配和无效贡献过滤；Go 奖励输入校验测试覆盖货币字段边界。
- 本批次尚未实际运行 Go 测试、C++ 构建或数据库迁移；后续应在本地/部署环境执行验证。


## 10. 东方神通首轮落地（2026-11-24）
