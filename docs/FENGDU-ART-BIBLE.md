# 《洪荒》酆都与角色美术圣经 v1

> 目标：建立统一、可扩展、能在 Godot 4.x 与多人在线场景中稳定运行的东方幽冥 3D 美术体系。本文是制作规范，不代表其中的正式模型、贴图、动画或录音已经交付。

## 1. 视觉定位

### 三个视觉支柱

1. **东方阴司秩序**：唐宋建筑语汇、官署礼制、牌楼、重檐、斗拱、石阶、木构与青瓦；避免直接套用西式哥特城堡。
2. **幽冥但不全黑**：夜色、薄雾、潮湿石材、旧木与青铜为基底；魂火、符箓、轮回法器提供少量高亮识别。
3. **庄严中有生活感**：酆都是庞大城市，不是单一墓园；必须同时看见官署、轮回、商贸、居民和城防活动。

### 基础色彩

| 用途 | 色彩方向 | 建议 HEX |
|---|---|---|
| 城墙/基石 | 冷灰黑石 | #45414F |
| 屋瓦/阴影 | 蓝黑 | #242638 |
| 木构 | 暗红褐木 | #493B3C |
| 金属装饰 | 旧青铜 | #8E7657 |
| 官署点缀 | 暗紫 | #55416F |
| 魂灯主光 | 幽青 | #85C8C1 |
| 轮回法器 | 淡金 | #C4A36A |
| 危险预警 | 暖朱红 | #C75B4B |

魂火只用于灯、符、法器和少量灵体核心，不要让所有建筑边缘都发光。危险区域不能只靠颜色区分，必须配合形状、符号和音效。

## 2. 酆都城市分区与建筑语言

酆都城区必须保持宏大城市的尺度与功能分区。以下是已有布局的正式化方向：

| 分区 | 核心建筑/设施 | 视觉要求 |
|---|---|---|
| 南门与城防区 | 鬼门关、城墙、角楼、巡逻岗 | 高大厚重、门洞尺度足以容纳多人和大型坐骑；城墙连续但可分块加载 |
| 西北阴司官署区 | 阎罗殿系官署、审判厅、档案库、案牍廊 | 中轴严整、台阶与门庭突出等级；案牍、印玺、灯架作为近景细节 |
| 东北六道轮回区 | 六道轮回殿、轮回法轮、引魂台 | 建筑庄严、空间开阔，法轮是远距离地标 |
| 西南鬼市坊区 | 摊位、茶肆、铁匠铺、魂货仓 | 密度高、遮棚与招牌丰富，保持连续步行通道 |
| 东南居民坊区 | 院落、巷道、民居、井台 | 低层为主，屋顶高低错落，避免整城都是宫殿 |
| 城外渡口与荒野 | 忘川渡口、驿站、古道 | 与城区留出距离；忘川不能误做成血海 |
| 远方血海 | 血海岸、冥河道场 | 位于酆都城外远方，使用暗红/黑红水体与巨大尺度，不进入酆都城内总览 |

建筑模块必须有可复用的墙段、墙角、门洞、屋檐、柱、台阶、栏杆、灯柱、牌匾和装饰件。正式模型应有独立视觉网格与独立碰撞体，禁止把 GLB 自带碰撞当作服务器逻辑。

## 3. 角色模型规范

### 玩家主角

- 视觉高度约 1.8m，面朝 Godot -Z，脚底落在 Y=0。
- 基础服饰为修行者长袍/短披肩/腰带/靴子，轮廓清楚，避免大面积拖尾影响动作。
- 角色必须预留武器、头部、胸甲、腿部、鞋、背部、饰品挂点。
- 最低动作：idle、walk；正式动作集：run、attack、hit、death、技能施法、受身/翻滚。
- 玩家模型必须适配现有 `HHHumanoidAnimationDriver` 或经过明确的骨骼重定向；不得只因有 AnimationPlayer 就认定动作可用。

### 关键 NPC

| NPC | 轮廓识别点 | 道具/动作 |
|---|---|---|
| 孟婆 | 女性长者、发髻/玉簪、青绿色衣饰 | 忘忧汤碗、轻微搅汤/递碗动作 |
| 阴司判官 | 暗紫官袍、冠帽、宽袖 | 判卷、执笔、审视动作 |
| 阴兵守卫 | 深灰蓝甲、肩甲、长兵器 | 持戟站岗、巡逻、警戒 |
| 试炼使者 | 暗朱袍、令牌/腰牌 | 召集、指引、传送确认 |
| 鬼市铁匠 | 厚实围裙、护腕、锤具 | 锻打、翻看材料、交付 |
| 普通城民/商贩 | 低饱和布衣、差异化头巾/包袱 | 站立、交谈、搬运、交易 |

NPC 不能只用同一个人形换颜色。重要 NPC 至少需要独特头部/帽饰、服装轮廓、手持道具和专属待机动作。

## 4. 怪物美术规范

| 类型 | 体型/轮廓 | 动作与材质 |
|---|---|---|
| 荒原狼 | 四足、低重心、长吻与背脊 | 巡游、扑咬、受击、死亡；毛皮粗糙 |
| 铁骨兽魂 | 大型四足、骨甲外露、重型头部 | 沉重行走、蓄力砸击、受击、死亡；骨/铁分层 |
| 炽战残魂/战魂 | 人形重甲、武器轮廓明显 | 挥砍、冲锋、受击、死亡；暗红火星点缀 |
| 游祟/灵识游魂 | 漂浮、半透明、轮廓不规则 | 悬浮、聚能、冲击、消散 |
| 生机古魂 | 绿色灵核、枝叶/藤蔓特征 | 缓慢脉动、治疗/缠绕动作 |
| 疾风游魂 | 青色流线、风刃/旋涡轮廓 | 快速位移、风刃攻击 |
| 火属性游魂 | 橙红核心、火焰外壳 | 火球蓄力、爆裂、残焰消散 |
| 冰属性游魂 | 冷蓝核心、冰晶棱角 | 冰刺、冻结预警、碎裂死亡 |

怪物的体型、攻击范围和服务器判定不能由模型大小决定。模型只负责视觉；服务端伤害、位置和碰撞仍为权威。

## 5. 动画与技术标准

- 角色与怪物优先 GLB/glTF，必须包含可用骨架和实际动作轨道。
- 人形角色动作需检查骨骼映射；四足怪物不得套用人形动作；漂浮灵体不强求 walk/run。
- 待机/移动循环，攻击/受击/死亡单次播放；死亡动作结束后由现有实体生命周期处理清理。
- 模型网格建议单角色控制在可接受的移动端预算内；优先 1K/2K 贴图，远景使用低模/LOD。
- 模型正面、比例、脚底、武器方向、材质透明排序必须在第三人称实际镜头检查。
- 视觉模型不创建或覆盖网络实体、攻击判定、服务器寻路和奖励逻辑。

## 6. 音频规范

### 酆都城区声景

- 远景：低强度风声、远钟、城墙外荒野底噪。
- 中景：街巷人声氛围（避免可辨识真实语言录音）、摊位器物声、木构轻响。
- 近景：脚步、灯火/魂火、门扇、交互确认、法器反馈。
- 重要 NPC：孟婆碗/汤、判官案牍/印玺、守卫兵器、铁匠锻打，分别建立短音效主题。

### 战斗与机关

攻击、命中、重击、怪物攻击、受击、死亡、技能、拾取、机关预警和机关生效必须有不同的听觉轮廓。预警音必须先于伤害判定；同一音效不能在高频事件中无限叠加。所有音频通过 Music/SFX/UI 总线并受音量设置控制。

当前 `audio_manager.gd` 中的声音均为运行时合成占位音，不是正式录音。新加的酆都环境音、引魂钟、鬼门关轰鸣、游魂低语和 NPC 交互提示音仍需在实际设备上试听、调整响度与循环接缝。

## 7. 资产完成定义与发布门槛

一项资产只有同时满足以下条件才可标记为 verified：

- 原始下载地址、作者、包名/版本、具体许可和随包 LICENSE 已登记。
- 原始文件保留，导入文件路径稳定，修改记录可追踪。
- Godot 能正确导入，无缺失贴图、骨架错误或异常比例。
- 在 ArtPreviewStage/酆都场景/战斗镜头中完成视觉检查。
- 动作、声音和碰撞分别通过各自测试；不得以静态预览替代运行验证。
- 低配设备检查帧率、内存和贴图负载。

**当前实际状态**：程序化玩家、NPC、怪物和建筑原型已存在；玩家与六类 NPC 的可选 GLB 资源槽已接入；九类怪物 GLB 槽已存在；正式 GLB 尚未批量导入验收；酆都城区音效仍为合成占位。该状态必须在开发记录和对外说明中保持准确。
