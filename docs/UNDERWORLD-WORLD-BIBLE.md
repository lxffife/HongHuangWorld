# 冥界世界观与地理总纲

状态：第一版世界设定基线
适用项目：HongHuangWorld
范围：神话融合后的原创游戏设定，不作为历史宗教教义的逐字复原

## 一、创作原则与文化边界

本项目采用中国古代后土、幽冥、罗酆山、十殿阎罗、六道轮回等传统意象，并融合《封神演义》及后世洪荒题材的创作语汇。

需要区分：
- 后土作为大地神祇、幽冥与轮回相关信仰，有长期的传统文化背景。
- 《封神演义》原著并没有完整给出本项目采用的“后土—酆都—冥河—血海—十八层地狱”全套统一组织架构。
- 冥河老祖、阿修罗教、血海道场、血神子等完整组合，主要采用后世洪荒题材的通行创作形象。
- 本文中的神权关系、盟约、疆域与剧情均为游戏原创整合，不宣称是唯一的传统神话版本。

## 二、冥界三大权柄

### 后土娘娘：幽冥本源与轮回法则

- 地位：冥界至高本源神位。
- 权柄：幽冥根源、六道轮回法则、亡魂最终归宿。
- 角色原则：不日常处理鬼籍、税赋、治安和普通审判；通过神谕、法则和关键剧情影响冥界。
- “平心”可作为后土显化轮回之后的尊号/神格表达，不在第一版中拆成两个互相竞争的独立角色。
- 后土神域是游戏原创的神圣空间，不等同于历史地理上的某个可考城市。

### 酆都大帝：阴司行政与司法中枢

- 地位：后土幽冥法统之下的阴司最高行政统治者。
- 职责：亡魂登记、秩序维护、审判体系协调、阴兵调度、轮回流程执行。
- 城市：酆都天城是冥界规模最大的常住城市和行政中心。
- 城内主要机构：皇城、十王府、判官司、鬼籍司、功过司、轮回司、阴兵营、鬼市、亡魂驿馆。
- 酆都大帝与后土不是同一层级；阴司不得擅自改写六道轮回根本法则。

### 冥河老祖：血海自治领主

- 地位：血海之主，阿修罗文明的始祖与最高统领。
- 领地：幽冥血海及周边血海荒原、岛屿、深海和海底禁区。
- 势力：阿修罗诸王、修罗军团、血神子、血海诸部。
- 代表性法宝/意象：元屠、阿鼻、十二品业火红莲（具体设定和能力以游戏平衡为准）。
- 政治关系：与阴司是古老盟约下的平行势力，不是酆都大帝的下属，也不默认是纯粹反派。

## 三、幽冥古盟（原创剧情设定）

1. 后土建立六道轮回，使亡魂有序归宿。
2. 冥河在血海建立道场，阿修罗文明逐渐成形。
3. 双方订立幽冥古盟：阴司尊重血海自治；血海不得任意吞噬正常轮回亡魂；双方共同维系幽冥深处的古老封印。
4. 盟约并非永久和平。血潮异变、亡魂污染、封印松动和阿修罗内部派系冲突，可成为主线与阵营任务来源。

## 四、冥界地理层级

### 一级：冥界世界总览

总览地图采用独立的示意坐标空间，仅用于表达相对方位、远近层级和势力关系。示意坐标不是米制世界坐标，不用于角色移动、导航、碰撞或服务端区域判定。

### 二级：大型地理板块

- 酆都天城与周边阴司辖域：冥界人口、商业、行政与任务中心。
- 忘川流域：忘川河、奈何桥、孟婆亭、望乡台、渡魂驿站。
- 罗酆古神山：罗酆山、六天宫遗迹及古幽冥神系遗址。
- 十八层地狱：位于酆都阴司可管理的独立地下空间，不是酆都城中的普通楼层。
- 幽冥荒原：连接核心辖域与远方险域的广阔边境。
- 幽冥血海：远离酆都的独立大陆级远域，中间隔有荒原、山脉、古战场和关隘。
- 后土神域：象征幽冥本源与轮回法则的神圣空间，普通角色不可自由进入。

### 三级：可游玩区域与副本

- 酆都：皇城、十王府、判官司、鬼籍司、鬼市、阴兵营、外城、城门和驿站。
- 忘川：河岸、渡口、奈何桥、孟婆亭、望乡台。
- 血海：外围荒原、海岸、浅海、深海、沉船禁区、漩涡、修罗魔宫。
- 十八层地狱：每层有独立环境、规则、守将、任务和挑战；阿鼻无间作为最深层核心禁区，不额外算作第十九层。
- 罗酆山：山门、六天宫遗址、古神封印与探索区域。

## 五、十八层地狱设计约束

十八层地狱采用民间流传意象与游戏原创关卡融合，不宣称下列名称是所有典籍统一的经典次序。每层需要具备独立的环境机制、战斗机制、探索目标与剧情，不以换色洞穴重复堆叠。

阿鼻/无间作为第十八层最深处的核心禁区或最终空间表达；不要把它误写成佛教分类中固定的“第十九层”。

地狱既承担罪魂刑罚，也可以承担危险存在镇压、远古封印与高风险剧情。不得把所有亡魂都设定为必须进入地狱。

## 六、世界地图与运行时坐标边界

- 当前酆都 256m × 256m 地形仍是隔离的技术样板，不代表酆都城市最终规模。
- 样板中的血海岸线只是临时地形生成测试几何，不是血海与酆都相邻的正式设定。
- 世界总览的示意坐标与各区域的实际游戏坐标必须分离。
- 各大型区域未来拥有独立的服务端 world/region 标识、出生点、POI、移动边界、怪物生态和加载策略。
- 客户端 atlas 只负责展示；实际入口、权限、传送、跨区移动、探索发现和危险判定必须由服务端权威数据决定。
- 总览图中的连线表示叙事/交通联系，不代表无条件可通行的道路，也不承诺实际旅行时间。
- 血海的实际地图尺寸、酆都到血海的真实里程、跨区交通方式，须待服务端世界拓扑与区域地形方案确定后再定，不在第一版伪造公里数。

## 七、阵营玩法原则

- 阴司阵营：秩序、审判、鬼籍、巡查、阴兵任务。
- 阿修罗阵营：血海生存、血脉成长、修罗战争、深海探索。
- 中立修行者：探索、交易、委托、两方声望。
- 阵营选择不应过早锁死角色全部玩法；后期可通过声望、盟约、剧情选择改变关系。
- 冥河不默认邪恶，酆都也不默认绝对正义；冲突由具体势力、利益和剧情触发。

## 八、十八层地狱推进规则（服务端策略基线）

- 地狱共 18 层，按层逐级开放；只有完成当前层的关卡目标并击败本层守将，服务端策略才允许解锁下一层。
- 已通关的层数允许重复进入；尚未开放的后续层不能通过客户端参数跳层。
- 第十八层是阿鼻/无间最深层核心禁区，通关后流程结束，不创建第十九层。
- 失败条件彼此独立：目标未完成、守将仍存活、层数无效、层数未解锁、重复提交完成请求都会得到不同结果，避免客户端把视觉击杀或传送当作通关。
- C++ `HellTrialProgression` 保留为 WorldServer 规则单测；中心服 Go 包 `Backend/internal/helltrial` 已提供角色进度查询、入层记录和通关结算服务。
- 数据库迁移 `000072_hell_trial_progress` 为世界实例增加可空 `hell_floor`（1–18），并按 `character_id + floor_number` 持久化解锁/通关状态、进入次数、时间和目标快照。
- 玩家查询接口：`GET /api/v1/characters/current/hell-trials`，通过账号当前肉身与活动世界会话解析进度，不接受客户端传入角色 ID。
- WorldServer 入层接口：`POST /api/v1/servers/hell-trials/entries`；通关接口：`POST /api/v1/servers/hell-trials/completions`。均要求 `X-World-Server-Key` 与 `X-World-Server-Node`，中心服核对角色活动会话确实由该节点承载，且世界实例 `hell_floor` 与请求层数一致。
- 玩家进入某一层的服务端票据接口：`POST /api/v1/worlds/hell-trials/{floor}/enter`（Bearer 账号令牌）。中心服只会为已解锁楼层签发票据，并只选择 `world_instances.hell_floor` 精确匹配的专属实例；普通 `POST /api/v1/worlds/enter` 明确排除所有地狱专属实例，避免普通酆都入口误分配到某一层。
- 入层事件和通关事件均使用 UUID 幂等；未记录入层、未完成目标、守将未败、层数未解锁均不能结算。当前层完成与下一层解锁在同一数据库事务内提交。 回调携带原始 `session_id`，中心服按节点与实例验证原始会话记录，并允许断线后的补交事件。
- **本轮新增的运行时接线**：WorldServer 支持 `WORLD_SERVER_HELL_FLOOR=1..18` 专属层实例配置；心跳会把层号写入 `world_instances.hell_floor`。角色通过地狱楼层票据进入专属实例后，WorldServer 在玩家成功加入时生成 UUID 入层事件并写入本地 SQLite durable outbox，后台线程重试调用中心服入层接口。普通世界配置使用 `WORLD_SERVER_HELL_FLOOR=0`。
- **本轮新增的关卡运行时**：WorldServer 根据 `WORLD_SERVER_HELL_FLOOR` 加载对应层的 3 个指定目标怪物和 1 个守将；十八层各有独立的怪物定义 ID、守将 ID、名称和推荐等级。目标怪物按稳定刷新点只计数一次，守将死亡与目标数量两项条件缺一不可。满足条件后，WorldServer 为当前专属实例的在线角色生成通关事件，写入 SQLite durable outbox，再调用中心服通关接口。中心服同时核对楼层、目标数量、目标快照来源和该层预设守将 ID，防止把其他层守将或普通怪物击杀当作通关。怪物配置热刷新不会移除专属地狱实例的内置遭遇怪物。\n- **仍待完成的内容**：当前每层已有基础静态遭遇（3 个目标怪物 + 1 个守将），但还没有多波次刷怪、动态难度、队伍贡献资格、失败/重置流程、各层独立地形与环境机关，也没有 Godot 端十八层入口 UI、传送流程和专属场景。遭遇计数目前是 WorldServer 进程内状态，服务器重启会重置当前轮遭遇；中心服已提交的玩家通关进度不受影响。当前可以验证服务器权威的基础通关闭环，但不能把它描述为完整副本内容。

## 九、当前实现状态

- `world_map_catalog.gd`：包含第一版冥界示意总览节点和关系连线。
- `world_map_view.gd`：支持本地地图与冥界总览两种显示模式。
- `world_scene.gd`：在酆都世界地图面板提供“冥界总览”切换入口。
- 现阶段是客户端示意图和设定目录，不代表大型区域已在服务器创建或可实际进入。
- 当前未实现跨区域移动、真实世界里程、血海独立服务端地图、十八层地狱场景及阵营权限。
