# 十八层地狱关卡设计草案

> 本文是《洪荒》的游戏化改编方案，不宣称各地民俗、宗教典籍对十八层地狱的名称和排列完全一致。正式剧情以游戏世界观为准。

## 关卡定位

十八层地狱不是酆都城内的普通副本，而是远离主城、由阴司监管的独立刑狱区域。入口设置在幽冥古道尽头；宏观地理预览中与酆都、血海分离。血海归冥河老祖势力范围，地狱的管理权属于后土娘娘统辖下的阴司体系，二者不应混成同一势力或同一地图。

## 核心游玩循环

1. 在入口关隘登记队伍、补给、确认难度与挑战规则。
2. 逐层推进：每层包含环境机制、普通敌人、一个明确目标（击败守狱者/解除封印/护送魂灯/关闭刑具机关）。
3. 每三层设置一个镇魂驿安全节点：恢复、整理战利品、选择继续或撤离。
4. 第 3、6、9、12、15 层设置阶段守关战；第 18 层为终审首领战。
5. 完成终审后开启通关出口与结算；失败时按副本规则返回最近安全节点或入口，不能静默丢失已结算奖励。

## 难度与奖励节奏

- 1–3 层：教会玩家读预警、识别机关、完成一次小队协作。
- 4–6 层：加入镜像与场地控制，第一次要求团队分工。
- 7–9 层：加入高风险移动与周期环境伤害。
- 10–12 层：增加群怪、预警连锁和机关优先级。
- 13–15 层：引入可叠加状态、护送与团队解救。
- 16–18 层：组合此前机制，最终首领不得只靠数值堆血。

奖励应采用服务器权威结算：经验、修为、冥币/冥石、材料和装备均由服务端决定；客户端只展示结果。阶段首领可掉落对应狱层材料，最终首领可掉落稀有制作材料/外观，不应让客户端本地生成可交易奖励。

## 关卡可读性与公平性

- 所有伤害机制先给出清晰预警，再进入判定窗口；预警颜色、形状和音效需能区分。
- 不使用只能靠颜色识别的机关，必须配合轮廓、符文或声音提示。
- 失败条件、复活点、撤离点和奖励保留规则必须在入口说明。
- 安全节点之间避免过长的无战斗空走廊；每层至少有一个可交互目标。
- 首领战阶段切换必须广播服务端事件，客户端特效不能作为伤害判定依据。
- 单人/组队难度、掉线重连、队伍中途加入、奖励归属与副本实例隔离需在服务端实现。

## 当前实现状态（2026-11）

### 已存在的运行时基础

- 酆都地图内有十八层试炼入口；客户端读取角色试炼名册，通过中心服申请专属楼层票据，再连接对应世界实例。
- 客户端按 `hell_floor` 构建对应楼层场景；试炼进度、阶段推进、守将阶段和完成状态由服务端广播。
- 世界服已有逐层试炼遭遇、波次导演、守将阶段控制、队伍贡献记录，以及耐久检查点/完成事件写入流程。
- 客户端试炼名册现直接显示每层 `WorldMapCatalog` 的目标描述，避免把所有楼层错误地显示成同一条“击败三类目标”。
- 客户端新增常驻试炼 HUD：显示楼层、当前波次/守将阶段、当前活动目标和服务端目标击杀进度；波次切换与守将阶段事件会刷新面板，离开刑狱实例会清理状态。
- HUD 只展示服务端下发的 `objective_kills`、`objective_required`、`stage`、`active_name`、`boss_phase` 与 `completed`，不在客户端推算或提交通关结果。

### 已落地的前三层视觉主题

- 第 1 层：三块证词石碑、回声拱环，建立“辨伪证词”的空间识别点。
- 第 2 层：交叉断缘剪刃、因果锚柱和断裂锁链，强化路径与时机主题。
- 第 3 层：铁树主干、倒刺枝杈、地面铁刺和受困魂灯，形成首个明显的关卡地标。
- 新增 `scenes/HellFirstThreePreview.tscn` 并排总览场景，可脱离服务器直接检查三层的主题布景、比例和整体辨识度。
- 这些新增物件目前是静态视觉布景，不提供客户端权威伤害、机关交互或目标完成判定；所有伤害和结算仍必须由服务端决定。

## 第一层：拔舌地狱证词调查

- 第一层新增三处可调查证据点：西侧卷宗案台（X=-10，Z=-3）、北侧回声石柱（X=0，Z=-10）、东侧魂灯台（X=10，Z=-3）。客户端灰盒场景已为三处线索添加不同的实体标识和名称牌；玩家必须靠近对应位置 5 米内才能提交答案。
- 每处线索有三种解释选项，世界服验证正确答案并维护全队共享的 0/3 至 3/3 进度；错误答案不推进，重复正确提交不会重复计数。
- 三份证词全部核验后，世界服广播结论：有人在三更后从西廊进入并替换罪簿。该调查目前是首层附加调查目标，不会绕过原有服务端波次与守将结算。
- 当前证据进度保存在世界服实例运行内存中；进程重启会重置调查状态，后续需接入持久化检查点。

## 当前原型边界

### 逐层提示数据

`HellTrialFloorSpec` 现为18层分别保存试炼提示与守将提示。世界服初始快照和波次事件都会同步楼层名称、试炼提示、守将提示；客户端常驻 HUD 根据阶段切换显示。提示是关卡主题与战斗建议，不代表尚未实现的机关已经生效。单元测试检查每层提示字段非空。


`scenes/EighteenHellsPreview.tscn` 仍是十八层垂直布局总览灰盒，不是可直接游玩的完整地狱副本。运行时的逐层实例和试炼波次已经存在，但当前前三层主题布景尚未升级为可交互机关；导航网格、预警/判定时序、救魂/证词/因果线交互、阶段安全节点和多人机制仍需逐项落地。不能把视觉布景描述成已完成玩法。

## 下一步实施顺序

1. 将前三层的关键地标转为可交互目标，并定义稳定的 `hell_objective_id`；客户端只负责输入与反馈。
2. 服务端为每层维护目标状态、交互冷却、队伍归属与完成条件，防止客户端伪造完成。
3. 为剪刃、铁枝等危险机制增加服务端预警时间窗与命中判定；客户端只呈现预警和动画。
4. 将每层拆为可复用的 PackedScene / 场景构建模块，保留当前 `hell_floor` 与世界票据协议。
5. 完成前三层多人测试：队伍同步、掉线重连、死亡回退、重复交互、奖励归属与持久化。
6. 再按前三层验证通过的模板扩展第 4–18 层。


## 第二层：断缘剪刃时序机关（服务端首版）

- 世界服新增 HellTrialShearHazard，仅在第二层启用，按固定周期运行：预警 2.5 秒、剪刃合拢 1.8 秒、回收安全期 3.7 秒。
- 中央刑道危险判定范围为 X[-9,9]、Z[-9,5]；两侧 X[-27,-12] 与 X[12,27] 为安全通道。场景中的剪刃与两侧锚柱对应这套空间规则。
- 服务端在阶段切换时向本层玩家广播预警/危险/回收事件；危险窗口内，处于中央区域的玩家每个周期最多受到一次 18 点伤害，护盾先吸收，死亡沿用现有死亡持久化流程。
- 客户端只播放预警音效和文字提示，不计算危险区、不提交伤害结果。离开危险区可规避伤害。
- 当前机制是矩形区域判定与周期切换的第一版；剪刃的动态模型动画、碰撞形状同步，以及第三层救魂机关尚未接入。


## 第三层：铁树地狱双人魂灯救援（服务端首版）

- 第三层新增两盏受困魂灯，分别位于西侧 X=-12、Z=-18 与东侧 X=12、Z=-18；玩家需在对应魂灯 5 米内提交交互。
- 首名玩家点亮一侧魂灯后启动 15 秒接应窗口；必须由另一名不同角色点亮另一侧魂灯，才能完成 2/2 救援。相同角色不能独自完成两侧交互，同一盏魂灯也不能重复计数。
- 世界服负责楼层、存活状态、位置、交互频率、灯位和角色身份校验；成功进度广播给当前实例全体玩家。快照会同步当前点亮侧、倒计时和完成状态。
- 客户端 HUD 提供两侧魂灯交互入口和协作状态提示；客户端不决定救援成功。救援目前是附加协作目标，不会绕过现有击杀波次/守将通关条件。
- 当前救援进度存在世界服内存中，进程重启会重置；本阶段未接入持久化检查点。单人无法完成该双人协作目标，后续应补充单人替代机制或明确副本人数要求。
