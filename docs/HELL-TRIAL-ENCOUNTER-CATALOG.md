# 十八层地狱遭遇目录（第一阶段）

这是游戏原创融合版的玩法目录。名称参考民间流传的十八层地狱意象，不宣称各类传统文献都采用完全相同的次序。

每层第一阶段统一为：击败 3 个指定目标怪物，再击败本层守将。目标怪物是三个不同的固定刷新点，按刷新点 runtime ID 去重；同一刷新点的后续复活不重复计数。

## 服务器判定

- 客户端不能提交击杀数量或守将死亡状态。
- WorldServer 只在真实怪物进入死亡结算路径时记录遭遇进度。
- 普通怪物、其他楼层怪物和同一刷新点重复死亡不会增加目标数量。
- 必须同时满足目标数和本层守将死亡，才会生成通关事件。
- 每位当前在线玩家各有独立 UUID 通关事件；事件进入 SQLite durable outbox 后异步投递中心服。
- 中心服还会复核目标快照、层数、目标数量以及本层守将 definition ID。

## 设计限制与后续迭代

第一阶段使用固定的 3 个目标刷新点和 1 个守将，目的是先验证权威击杀与进度结算链路。各层目前还没有真正独立的地形、陷阱、环境规则、分阶段 Boss 技能或波次导演。遭遇计数是进程内状态，重启后未完成的当前轮会重新开始；已由中心服提交的通关进度不会回滚。

后续应将每层遭遇配置迁移为可版本化的 JSON/数据库配置，加入波次、机关、Boss 阶段、队伍参与资格和失败重置规则，再与 Godot 独立场景对接。
