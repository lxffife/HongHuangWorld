# 十八层地狱遭遇目录（第一阶段）

这是游戏原创融合版的玩法目录。名称参考民间流传的十八层地狱意象，不宣称各类传统文献都采用完全相同的次序。

每层第一阶段统一为四段顺序遭遇：本层目标一 → 本层目标二 → 本层目标三 → 本层守将。第一层对应割舌鬼、罪簿吏、回声冤魂和拔舌判官；其他楼层使用表格中的专属名称。后续波次和守将处于休眠状态，只有前一阶段的服务端权威死亡结算完成后才会激活。目标怪物按每次怪物生命的唯一 ID 去重：同一生命的重复死亡回调只计一次；本层三只目标各计一次，总数封顶为 3。

## 服务器判定

- 客户端不能提交击杀数量或守将死亡状态。
- WorldServer 只在真实怪物进入死亡结算路径时记录遭遇进度。
- 普通怪物、其他楼层怪物和同一怪物生命的重复死亡回调不会增加目标数量；新生命可计数，但总数封顶为 3。
- 必须同时满足目标数和本层守将死亡，才会生成通关事件。
- 玩家必须先成功进入该层，并累计至少相当于一只目标怪物基础生命值 10% 的有效贡献，才具备通关奖励资格；怪物有效伤害按 1:1 计入，治疗其他玩家的实际恢复量按 1:0.5 计入，自疗和过量治疗不计入。单纯进入副本、挂机或在通关后进入均不会自动获得通关奖励。
- 贡献按角色累计，断线后以新会话重新进入同一层时保留本次 WorldServer 进程内的累计有效贡献；资格使用当前已验证的角色会话投递独立 UUID 通关事件，事件进入 SQLite durable outbox 后异步投递中心服。
- 中心服还会复核目标快照、层数、目标数量、本层守将 definition ID，并独立重算该层贡献门槛，拒绝不足贡献或伪造门槛的完成事件。

## 设计限制与后续迭代

当前 18 层都使用四段顺序遭遇骨架；第一层拔舌地狱额外启用守将三阶段强度变化：生命值高于 65% 为审判阶段，降至 65% 进入刑罚阶段（攻击 ×1.25、动作节奏 ×0.90），降至 30% 进入无间狂怒阶段（攻击 ×1.60、动作节奏 ×0.75）。阶段只升不降，治疗守将不会让阶段回退。波次阶段和对应目标击杀数以 WorldServer SQLite `instance_key + floor` 检查点持久化，并在重启后恢复；最终通关事件批量入队成功后才写入最终阶段。玩家贡献账本目前仍是进程内状态，WorldServer 重启后未结算贡献会重新开始；已由中心服提交的通关进度不会回滚。各层仍待制作独立精细地形、刑具机关、范围技能预警和专属动画。

后续应将每层遭遇配置迁移为可版本化的 JSON/数据库配置，加入波次、机关、Boss 阶段、队伍参与资格和失败重置规则，再与 Godot 独立场景对接。
