# 十八层地狱遭遇目录（第一阶段）

这是游戏原创融合版的玩法目录。名称参考民间流传的十八层地狱意象，不宣称各类传统文献都采用完全相同的次序。

每层第一阶段统一为：击败 3 个指定目标怪物，再击败本层守将。目标怪物按每次怪物生命的唯一 ID 去重：同一生命的重复死亡回调只计一次；同一刷新点复活后形成的新生命可以再次计数，但本层目标总数封顶为 3。

## 服务器判定

- 客户端不能提交击杀数量或守将死亡状态。
- WorldServer 只在真实怪物进入死亡结算路径时记录遭遇进度。
- 普通怪物、其他楼层怪物和同一怪物生命的重复死亡回调不会增加目标数量；新生命可计数，但总数封顶为 3。
- 必须同时满足目标数和本层守将死亡，才会生成通关事件。
- 玩家必须先成功进入该层，并对本层怪物造成至少相当于一只目标怪物基础生命值 10% 的有效伤害，才具备通关奖励资格；单纯进入副本、挂机或在通关后进入均不会自动获得通关奖励。
- 贡献按角色累计，断线后以新会话重新进入同一层时保留本次 WorldServer 进程内的累计伤害；资格使用当前已验证的角色会话投递独立 UUID 通关事件，事件进入 SQLite durable outbox 后异步投递中心服。
- 中心服还会复核目标快照、层数、目标数量以及本层守将 definition ID。

## 设计限制与后续迭代

第一阶段使用 3 个目标怪物定义和 1 个守将，目的是先验证权威击杀与进度结算链路。各层目前还没有真正独立的地形、陷阱、环境规则、分阶段 Boss 技能或波次导演。遭遇计数与参与贡献账本目前仍是进程内状态，WorldServer 重启后未完成的当前轮及未结算贡献会重新开始；已由中心服提交的通关进度不会回滚。

后续应将每层遭遇配置迁移为可版本化的 JSON/数据库配置，加入波次、机关、Boss 阶段、队伍参与资格和失败重置规则，再与 Godot 独立场景对接。
