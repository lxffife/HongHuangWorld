# 网络协议约定

P0 使用独立的版本化协议，客户端和 C++ 世界服务器共用字段定义。协议定义与传输实现分离。

## 传输

- 业务 API：HTTPS + JSON。
- 实时游戏：UDP + ENet。
- ENet 负责可靠/不可靠传输通道；应用层仍需定义消息类型、协议版本、序列号、实体 ID 和校验规则。

## 实时消息建议

- ClientHello：协议版本、连接票据、客户端构建版本。
- ServerWelcome：玩家实体 ID、世界/实例 ID、服务器 tick、初始快照。
- InputCommand：输入序列号、客户端采样时间、移动/动作意图。
- EntitySnapshot：服务器 tick、实体 ID、位置、朝向、速度和状态标记。
- PlayerJoined / PlayerLeft：实体进入/离开 AOI 的事件。
- Heartbeat / HeartbeatAck：连接健康检查。

## 安全规则

服务端验证票据、协议版本、消息大小、序列号、输入频率、移动速度和状态转换。客户端发来的坐标仅作为输入意图或预测参考，不能直接成为权威状态。

## 兼容性

协议必须有明确版本号；不兼容变更提升主版本。协议变更需同时更新 Godot 客户端、C++ 服务端和协议测试。不得把语言内存布局直接作为网络格式。

## 世界入口票据握手（P0）

1. 客户端使用账号 Bearer Token 调用 `POST /api/v1/worlds/enter`。
2. 中心后端根据角色当前世界、节点心跳、实例状态和容量选择目标节点，签发 60 秒有效的一次性随机票据。数据库只保存票据 SHA-256 摘要。
3. 客户端使用 ENet 连接返回的 UDP 地址，并在应用层 `ClientHello` 中携带票据与协议版本。
4. C++ 世界服务器通过受保护的 HTTPS `POST /api/v1/servers/tickets/redeem` 兑换票据，提交自身 `node_key`。后端校验票据未过期、未消费且目标节点匹配，原子消费票据并创建世界会话。
5. 后端返回角色 ID、世界/实例 ID 和初始位置快照；世界服务器以此恢复实体并发送 `ServerWelcome`。

票据只能使用一次。客户端断线后重新申请票据，不得复用旧票据。世界服务器 API Key 只用于服务器到后端的 HTTPS 管理调用，不能下发给客户端。
