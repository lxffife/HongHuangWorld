# 洪荒世界统一经济与修炼资源体系

状态：统一经济底座第一阶段（数据库结构、货币目录、钱包查询与账本原语已落地；兑换执行、修炼扣除业务、任务大厅接入仍待后续阶段）

## 1. 已确认的产品决策

1. 兑换采用混合机制：官方基础汇率 + 玩家市场浮动。
2. 修炼石同时是可交易资产和可消耗资源，可用于修炼、炼器、炼丹、阵法等。
3. 跨世界兑换逐步开放，必须满足世界进度、通道和势力权限条件。
4. 所有货币与修炼资源进入同一个玩家账号钱包；凡俗货币不可直接用于修炼。
5. 一个世界使用自己的货币名称和属性配置，但所有世界共用同一套经济代码、账户、账本和兑换引擎。

## 2. 三层资产分类

| 层级 | 分类 | 示例 | 交易 | 直接修炼 |
|---|---|---|---|---|
| 凡俗货币 | fiat | 金币、银币、铜钱、冥币、魔币、妖币、仙钱 | 是 | 否 |
| 修炼货币 | cultivation | 灵石、冥石、魔石、妖石、仙晶、佛晶、龙晶、巫晶 | 是 | 是，受体质/功法适配影响 |
| 世界战略资源 | origin | 世界本源晶、天道碎晶、混沌源晶 | 默认受限 | 仅特定高阶玩法 |

资产分类不是世界专属代码。新增世界时只需添加世界货币规则、资源属性、发行渠道和兑换对，不应复制钱包或交易服务。

## 4. 钱包与资产归属

- 钱包归属 Identity 签发的玩家账号 UUID，不归属当前肉身角色，也不归属单一世界。经济库不复制账号凭据，也不对 Identity 账号表建立外键；通过账号 UUID 和事务级 advisory lock 保证钱包隔离与并发串行。
- 玩家轮回、切换种族、跨世界移动时，账号资产不重置。
- 每种货币分别保存可用余额和冻结余额，金额统一使用 BIGINT 整数，不使用浮点数。
- 物品背包仍保存可堆叠装备/材料等物品；货币与可作为货币交易的修炼石走统一钱包。不可交易的任务道具仍走背包。
- 世界服务、客户端不能直接更新余额；余额变化必须通过经济领域服务并产生账本记录。
- 每个业务事件使用稳定 event_key 幂等；同一事件重放返回既有结果，不重复增减余额。
- 账本记录保留变更前后可追踪信息；数据库触发器阻止历史流水被 UPDATE/DELETE，纠错只能追加反向冲正流水。

## 5. 修炼与制造规则

凡俗货币的 currency_class 为 fiat，cultivation_usable 固定为 false。服务端执行 cultivation 消耗时必须再次检查货币目录，不接受客户端自报“可修炼”。

修炼货币记录能量属性、品质等级和兼容效率。兼容效率按目标标签配置，例如：

- spirit_stone + all：基础适配。
- nether_stone + race:ghost：幽冥体高适配。
- demon_stone + race:demon：魔族高适配。
- buddhist_crystal + path:buddhist：佛门功法高适配。

适配效率只决定单位资源的有效能量，不直接等于最终属性增长。修为、境界、功法、体质、当前状态、修炼环境和每日/阶段上限仍由服务端成长规则共同计算。未来增加高品质资源时，应按质量等级配置吸收效率、纯度与突破适配，不能仅通过提高货币面值无限抬高战力。

炼器、炼丹、布阵使用独立 action_key 配方消耗；石头可以作为货币交易，也可以在制造行为中消耗。凡俗货币可以支付工匠服务费，但不能替代灵气/冥气等核心材料。

## 6. 官方汇率 + 市场浮动

每个兑换方向有官方基础比例（整数分子/分母）、手续费、允许市场偏离区间和解锁条件。

建议执行顺序：
1. 检查玩家是否解锁来源世界、目标世界和跨界贸易通道。
2. 读取有效市场报价；市场无足够成交量或报价过期时回退官方汇率。
3. 将市场报价限制在官方汇率允许的偏离走廊内，防止单笔异常报价操纵。
4. 计算兑换数量和手续费，所有运算使用整数/定点数，明确向下取整规则。
5. 锁定玩家来源余额与兑换储备，验证储备充足。
6. 在一个数据库事务中扣来源资产、扣手续费/增加财政、增加目标资产、更新储备、写兑换事件和双方账本；任一步失败全部回滚。
7. 记录使用的汇率、报价来源、手续费、市场报价 ID 和事件幂等键。

官方基础汇率不是无限承诺的无条件兑换价。官方兑换必须受储备数量和每日额度约束；玩家市场交易必须受市场深度和风控限制。世界本源类战略资源默认不可自由兑换。发行必须匹配世界/货币/来源白名单及额度，不能仅凭客户端请求增加资产。

首批示例比例只是系统初始化测试值，不代表永久平价或最终经济平衡。正式运营前需要根据资源产出、消耗、跨界流量和市场深度重新定价。

## 7. 逐步开放跨世界经济

跨界兑换需要同时满足：
- 目标世界已经开放并允许玩家进入。
- 玩家取得跨界贸易/传送权限。
- 两个世界的货币规则允许兑换。
- 对应兑换对已启用且有可用储备或有效市场深度。
- 玩家达到该世界要求的剧情、境界或势力条件。

解锁状态按 account + world + unlock_key 记录。世界入口开放不等于经济兑换自动开放；可以先允许玩家进入世界，再开放本地交易，最后才开放跨界兑换。黑市是额外渠道，可使用更高手续费、更大汇率偏差和更高风险，但不能绕过资产账本或凭空创造资产。

## 8. 首批数据库和 API

迁移：`000052_unified_economy_foundation`

核心表：
- `currency_definitions`：货币名称、类别、所属世界、能量属性、品质、是否可修炼/交易/跨界。
- `currency_world_rules`：世界使用的货币、主货币、发行和兑换开放条件。
- `currency_issuance_policies`：按世界、货币和可信来源限制单次发行上限与每日发行上限。
- `currency_balances`：账号统一钱包的可用/冻结余额。
- `economy_ledger_entries`：不可变资产流水和幂等键。
- `economy_escrows`：任务、拍卖等用途的托管资产。
- `economy_treasury_accounts` / `economy_treasury_balances` / `economy_treasury_ledger_entries`：各世界城主府、世界公库、势力财政和兑换储备的独立财政账户与流水。
- `currency_cultivation_affinities` / `currency_cultivation_costs`：修炼适配与制造/修炼消耗配置。
- `currency_exchange_pairs`：官方汇率、市场偏离走廊、手续费和解锁条件。
- `currency_exchange_reserves` / `currency_market_quotes` / `currency_exchange_events`：储备、市场报价和兑换执行记录。
- `account_world_economy_unlocks`：玩家逐步解锁跨界经济的记录。

已接入只读接口：
- `GET /api/v1/economy/currencies`：公开货币目录。
- `GET /api/v1/economy/wallet`：Bearer 认证后读取当前账号的统一钱包。

`internal/economy.Service.ApplyDelta` 是单币种可用余额增减原语：账号 advisory lock、余额行锁、整数余额校验、事件幂等和账本插入在同一事务中完成。它只接受发放、普通消费、修炼消耗、制造消耗和受控系统冲正；不允许把托管冻结/释放、玩家转账或兑换拆成互不关联的单边调用，这些操作必须由专用用例在同一事务内同时处理双方余额、冻结额、财政和流水。它是领域服务方法，不开放给客户端直接调用。当前尚未把它接入玩家任务奖励、世界掉落、修炼、炼器或兑换 HTTP 命令。

## 9. 与现有系统的边界

- Identity 负责认证并提供 account ID；经济系统只使用已认证 account ID，不管理密码、会话或登录。
- Chat 不依赖经济系统；经济服务故障不应影响聊天或角色移动。
- WorldServer 只提交经过可信节点身份验证的游戏事件；不能提交任意金额、汇率或客户端自报奖励。
- 经济系统负责钱包、托管、账本、兑换与财政；成长系统负责根据服务端规则计算修为和属性。
- 任务大厅的发布费、悬赏冻结、结算税和退款后续统一迁移到 economy ledger/escrow。当前 Godot 酆都任务大厅仍是内存演示原型，不能与正式钱包混用。

## 11. 经济安全原则

- 金额只使用 BIGINT；汇率只使用整数分子/分母或基点，不使用 float。
- 任何余额变动都必须有 event_key 和 ledger entry。
- 账户/余额行锁保证并发扣款不会透支；唯一幂等键保证重试不会重复发放。
- 兑换、托管和结算必须原子提交。
- 客户端不能决定奖励数量、税率、汇率、资源消耗或交易是否成功。
- 世界本源资源、官方储备和系统发行额度必须有独立权限和审计。
